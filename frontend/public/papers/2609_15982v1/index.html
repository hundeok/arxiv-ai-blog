> **원본 논문 정보**
> - **제목:** The Router Within: Eliciting Native Skill Routing from a Frozen LLM
> - **저자:** Ruishuo Chen, Xun Wang, Yu Chen, Zhuoran Li, Longbo Huang
> - **발행일:** 2026-09-14
> - **PDF 링크:** [The Router Within: Eliciting Native Skill Routing from a Frozen LLM](https://arxiv.org/pdf/2609.15982v1)


✨ 3줄 핵심 요약
* **Gavel**은 추가적인 학습 없이 LLM 내부에 이미 존재하는 스킬 라우팅 신호를 두 개의 선형 투영(linear maps)만으로 추출하는 기술입니다.
* 스킬 메타데이터를 컨텍스트에 삽입하는 기존 방식과 달리, 컨텍스트를 오염시키지 않으면서도 외부 모델 없이 모델 스스로 적절한 스킬을 선택하게 합니다.
* Qwen3-32B 모델 적용 시 기존 방식들보다 성능이 대폭 향상되었으며, 특히 실시간 작업 중 스킬이 필요한 상황에서 탁월한 정확도를 보입니다.

📖 쉽게 풀어쓴 1분 핵심
AI 에이전트가 특정 업무를 수행할 때 외부의 '스킬(도구, 지침)'을 가져다 쓰는 것은 매우 중요하지만, 현재는 스킬 목록을 AI의 기억 공간(컨텍스트)에 전부 넣어야 해서 AI가 혼란을 겪거나 성능이 저하되는 문제가 있습니다. 연구진은 LLM 자체가 이미 어떤 상황에 어떤 스킬이 필요한지에 대한 정보를 알고 있다는 점에 착안했습니다. **Gavel(Glance and Verdict)**은 LLM의 중간 레이어 상태를 읽어내는 두 개의 단순한 선형 변환기만으로 이 정보를 추출합니다. 마치 AI가 스스로 스킬 메뉴를 보고 판단하는 것과 같아, 별도의 외부 모델 없이도 효율적으로 정확한 스킬을 골라냅니다.

🎯 배경 및 문제점
* **기존의 한계:** 스킬 라이브러리가 수만 개 단위로 커짐에 따라, 메타데이터를 프롬프트에 넣는 '점진적 공개(progressive disclosure)' 방식은 AI의 컨텍스트 창을 점유하여 본래 작업 성능을 떨어뜨립니다.
* **외부 모델의 한계:** '검색 후 순위 재조정(retrieve-and-rerank)' 방식은 컨텍스트를 깨끗하게 유지하지만, 스킬 선택을 에이전트 외부의 별도 모델에 의존해야 하므로 모델 전체의 이해도를 활용하지 못합니다.
* **핵심 과제:** 모델 자체의 성능을 저하시키지 않으면서, 수많은 스킬 라이브러리 중 당면 과제에 최적화된 스킬을 스스로 선택하게 하는 효율적인 라우팅 체계가 필요합니다.

💡 핵심 기술 및 아키텍처
* **Gavel 메커니즘:** 
    * **Glance(훑어보기):** 태스크와 각 스킬의 중간 레이어 상태를 학습된 두 개의 선형 투영(7.9M 파라미터)으로 투사하여 스킬 라이브러리 전체의 점수를 매깁니다.
    * **Verdict(판결):** 후보 스킬들을 대상으로 모델 자체의 확률과 'Yes/No' 판단을 결합하여 최종적으로 스킬 사용 여부를 결정합니다.
* **레이어 선택:** 64개 레이어 중 44번째 레이어(전체 깊이의 약 70%)가 가장 최적의 라우팅 신호를 포함하고 있음을 실험적으로 확인했습니다.
* **제로샷 전이:** 한 번 학습된 Gavel은 별도의 추가 튜닝 없이 여러 공개 벤치마크 및 372개의 시뮬레이션 에이전트 궤적(SkillTraj)에 바로 적용 가능합니다.

📊 실험 결과 분석
* **성능 향상:** Qwen3-32B 모델에서 1.2B~16B 파라미터를 추가하는 기존 방식 대비, 문서 기반 작업에서 최대 13.4포인트, 작업 도중 스킬이 필요한 상황에서는 최대 21.9포인트의 성능 향상을 기록했습니다.
* **우수한 효율성:** Bash-agent 환경에서 32B 모델에 적용했을 때, 훨씬 더 큰 규모의 프론티어 모델들이 Codex 환경에서 수행하는 것보다 더 자주 올바른 스킬을 호출했습니다.
* **수치적 상세:** 학습된 투영 행렬은 768 × 5120 크기이며, AdamW 옵티마이저를 사용하여 24,000단계 동안 학습되었습니다. (비용 관련 수치는 논문에 명시된 API 가격 기준에 따라 작업량 및 모델 크기에 의존적임)

🌍 세상에 미치는 영향 & 실무 적용 사례
* **API 서비스 최적화:** 클라우드 API 제공자가 라우터를 직접 호스팅하면, 클라이언트는 API 호출 시 추가적인 인프라 비용 없이 더 정확한 스킬 라우팅 결과를 얻을 수 있습니다.
* **컨텍스트 효율성:** 스킬 메타데이터를 프롬프트에 넣지 않아도 되므로, 제한된 컨텍스트 창을 오직 핵심 작업에만 집중할 수 있게 하여 에이전트의 전체적인 작업 완성도를 높입니다.
* **범용성:** 이 방식은 백본 LLM이 발전함에 따라 라우팅 정확도도 함께 상승하는 구조이므로, 차세대 대형 모델들에도 범용적으로 적용 가능한 미래지향적 인터페이스입니다.
