ASLEval: LLM 에이전트 세션의 개인정보 노출 변위 측정

ASLEval: LLM 에이전트 세션의 개인정보 노출 변위 측정

ASLEval: LLM 에이전트 세션의 개인정보 노출 변위 측정

> **원본 논문 정보**
> - **제목:** ASLEval: Measuring Privacy Exposure Displacement in LLM Agent Sessions
> - **저자:** Guosen Wu, Huizhen Huang, Guoxiong Long, Tao Huang, Chen Hou
> - **발행일:** 2026-09-16
> - **PDF 링크:** [ASLEval: Measuring Privacy Exposure Displacement in LLM Agent Sessions](https://arxiv.org/pdf/2609.18864v1)


✨ 3줄 핵심 요약
* 기존 LLM 에이전트의 개인정보 평가는 특정 결과물만 확인하는 국소적 방식에 의존하여 전체 세션 내 노출을 제대로 포착하지 못하는 한계가 있습니다.
* '개인정보 노출 변위(Privacy Exposure Displacement)' 개념을 통해 평가 프록시와 실제 노출 사이의 불일치를 정의하고 이를 측정하는 ASLEval 프레임워크를 제안합니다.
* 실험 결과, 기존 방식은 전체 노출의 상당 부분을 놓치며, 개인정보 보호 강화는 작업 효율성 저하를 초래할 수 있어 두 지표를 함께 고려해야 함을 확인했습니다.

📖 쉽게 풀어쓴 1분 핵심
LLM 에이전트가 도구를 사용할 때, 보안 담당자는 보통 최종 답변이나 특정 이메일 전송 결과만 확인합니다. 하지만 에이전트는 이 과정에서 콘솔 로그나 중간 피드백 등 다양한 경로로 정보를 노출할 수 있습니다. ASLEval은 세션 전체를 관통하는 '숨겨진 타겟 데이터셋'을 사전에 설정하고, 에이전트가 정보를 내보내는 모든 경로를 감시합니다. 이를 통해 단순히 눈에 보이는 결과뿐만 아니라, 시스템 내부에서 어떤 정보가 어떻게 유출되는지를 정확히 파악하여 평가의 사각지대를 제거합니다.

🎯 배경 및 문제점
* **기존 평가의 한계:** 현재의 개인정보 및 안전성 벤치마크는 최종 답변, 파일 공유 이벤트 등 단일 지점만을 검사합니다.
* **평가 프록시의 불일치:** 국소적인 평가 방식은 전체 세션에서 일어나는 비인가 노출을 놓치기 쉬우며, 외부 공격자 보고서와 실제 시스템 노출 사이에 괴리가 발생합니다.
* **측정 실패의 정의:** 저자들은 이를 '개인정보 노출 변위'라 명명하고, 평가 대상과 실제 노출 사이의 불일치를 분석하는 체계적인 방법론이 필요하다고 강조합니다.

💡 핵심 기술 및 아키텍처
* **ASLEval 프레임워크:** 세션 실행 전 타겟 데이터셋, 인가 관계, 가시적 출력 범위를 사전에 정의하는 권한 인식(Authorization-aware) 프레임워크입니다.
* **타겟 기반 판정기(Target-Grounded Adjudicator):** 세션 종료 후 기록된 모든 데이터를 분석하여 사전에 등록된 타겟 노출 여부를 판별합니다.
* **진단 지표:**
    * **C1(출력 경로 변위):** 특정 예상 경로 외의 다른 경로에서 발생하는 노출을 측정합니다.
    * **C2(인식 변위):** 공격자(프로브 에이전트)의 보고서와 실제 노출 간의 차이를 평가합니다.
    * **C3(경로 변위):** 내부 데이터가 도구 사용 흐름에 따라 어떻게 외부로 전달되는지를 추적합니다.

📊 실험 결과 분석
* **노출 누락:** 기존의 '예상 경로만 확인하는 방식'은 전체 노출의 46.9%를 놓치는 것으로 나타났습니다.
* **탐지 정확도:** 공격자 스스로 보고하는 방식은 노출을 누락하거나, 반대로 없는 유출을 있다고 하는 허위 발견(False discovery) 비율이 높았습니다.
* **보호와 효율의 트레이드오프:** 모델이 볼 수 있는 정보를 인위적으로 줄여 개인정보 노출을 방지하려 할 경우, 정상적인 업무 수행 성공률이 급격히 낮아지는 현상이 관찰되었습니다. (참고: 인간 평가자의 엄격한 F1 점수는 0.891~0.929 사이로 나타났으나, 구체적인 수치 외의 데이터셋 규모나 환경 설정값은 본 발췌문에 명시되지 않음)

🌍 세상에 미치는 영향 & 실무 적용 사례
* **평가 기준의 재정립:** 단순히 단일 결과물을 확인하는 수준을 넘어, 세션 내 모든 가시적 경계와 사전에 정의된 타겟을 기반으로 한 포괄적 평가의 중요성을 제기합니다.
* **실무적 제언:** 에이전트의 개인정보 보호 정책을 설계할 때, 단순히 개인정보 노출 차단 성능만 보지 말고 모델의 '개인정보 보호-업무 효율성(Privacy-Utility)' 프론티어를 함께 측정하고 보고해야 합니다.
* **보안 도구 개발:** 기업용 LLM 에이전트 시스템을 구축할 때, 감사 로그를 단순히 추적하는 것을 넘어 전체 세션의 문맥 내에서 데이터 흐름을 정밀하게 통제하고 진단하는 기술적 기반이 될 수 있습니다.
