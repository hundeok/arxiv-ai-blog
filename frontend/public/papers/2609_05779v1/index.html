> - **저자:** Andrej Andrejev
> - **발행일:** 2026-09-05
> - **PDF 링크:** [Diffs vs. Whole Files: An Empirical Comparison of Iterative Edit-Based and Direct Generation for Flutter/Dart Code Models](https://arxiv.org/pdf/2609.05779v1)


✨ 3줄 핵심 요약
- 코드 수정 시 전체 파일을 한 번에 생성하는 '직접 생성' 방식이 작은 단위의 편집을 반복하는 '차트(Diff) 기반 생성' 방식보다 모든 성능 지표에서 우수합니다.
- 차트 기반 방식의 낮은 성능은 단순히 프로세스 오류 때문이 아니라, 정상적으로 완료된 작업에서도 발생하는 의미적 일탈(drift)이 주된 원인입니다.
- 단, 수정 범위가 매우 좁고 국소적인 경우에는 차트 기반 방식이 경쟁력을 가지며, 이를 '작업 국소성(task locality)'이라고 정의합니다.

📖 쉽게 풀어쓴 1분 핵심
코드를 수정할 때 AI 모델은 두 가지 방법을 씁니다. 하나는 파일 전체를 새로 쓰는 '직접 생성'이고, 다른 하나는 수정할 부분만 찾아 고치는 '차트(Diff) 기반 생성'입니다. 인간 개발자는 보통 후자처럼 작업하지만, AI 모델에게는 파일 전체를 쓰게 하는 것이 코드의 정확도와 품질 면에서 훨씬 뛰어난 결과를 보여줍니다. 다만, 수정할 내용이 아주 적고 명확한 특정 상황에서는 차트 기반 방식도 충분히 효과적이라는 점을 확인했습니다.

🎯 배경 및 문제점
코드 에디팅 도구들은 인간의 작업 방식과 유사하고 효율적이라는 이유로 주로 '차트 기반 생성' 방식을 선호합니다. 하지만 이 방식이 훈련 과정에서도 최선의 전략인지는 논쟁이 있었습니다. 일부 연구는 차트 기반 방식이 더 나은 커리큘럼이라고 주장하고, 다른 연구는 이 방식이 잘못된 편집을 유도해 신뢰성을 떨어뜨린다고 지적합니다. 본 연구는 이 두 방식을 실제 성능 데이터로 비교 분석했습니다.

💡 핵심 기술 및 아키텍처
연구진은 100M 파라미터의 자체 모델과 Qwen2.5-Coder-0.5B 모델을 사용하여 각각 두 가지 방식으로 학습시켰습니다.
- **직접 생성(Direct Generation):** 지시사항을 바탕으로 수정된 전체 파일을 한 번에 출력.
- **차트 기반 생성(Iterative Diff-based Generation):** 검색/교체 형태의 편집 명령을 반복적으로 적용하여 최종 결과 도달.
연구진은 컴파일 통과율(dart_pass), 비트당 바이트 수, 참조 코드와의 유사도, LLM 심사위원의 코드 품질 평가 등을 통해 두 방식을 엄격히 비교했습니다.

📊 실험 결과 분석
모든 아키텍처에서 '직접 생성'이 차트 기반 생성보다 우세했습니다.
- **컴파일 통과율:** 직접 생성 방식이 차트 기반보다 39.9~45.5%p 더 높았습니다.
- **성능 격차의 원인:** 차트 기반 생성의 실패는 단순히 중간 단계에서 멈추거나 잘못된 형식을 출력하는 문제가 아니라, 정상적으로 작업이 완료된 후에도 발생하는 의미적 일탈 때문이었습니다.
- **예외적 경쟁력:** 차트 기반 생성은 리팩토링이나 오류 처리 등 수정 단계가 적게 요구되는 '작업 국소성'이 높은 경우에만 의미 있는 성과를 거두었습니다.

🌍 세상에 미치는 영향 & 실무 적용 사례
이번 연구는 코드 에디팅 AI를 설계할 때 무조건 '인간의 작업 방식을 흉내 내는 것'이 정답이 아닐 수 있음을 시사합니다. 실무에서는 작업의 성격에 따라 전략을 유연하게 선택하는 '적응형 포맷(adaptive-format)' 접근법이 필요합니다. 즉, 전체적인 수정은 직접 생성을 사용하고, 아주 작은 국소적 수정에만 차트 기반 생성을 선택하는 전략이 코드 생성 모델의 품질을 극대화할 수 있는 방향임을 제시합니다.
