> **원본 논문 정보**
> - **제목:** Should We Type or Talk to LLM Agents? A Comprehensive Study of Voice and Keyboard Input Perturbations
> - **저자:** Zizhao Hu, Nathan Elijah Segura, Mohammad Rostami, Jesse Thomason
> - **발행일:** 2026-08-04
> - **PDF 링크:** [Should We Type or Talk to LLM Agents? A Comprehensive Study of Voice and Keyboard Input Perturbations](https://arxiv.org/pdf/2608.03970v1)


✨ 3줄 핵심 요약
- 음성 입력의 전사(transcription) 과정에서 발생하는 구조적 변형은 LLM의 정확도를 저하시키며, 이는 단순히 '음, 어'와 같은 추임새 때문이 아니라 문장 구조 자체에 기인합니다.
- 키보드 오타는 모델이 비교적 잘 흡수하여 성능 영향이 적지만, 음성 입력 변형은 모델이 학습이나 적응을 통해 해결하기 어렵습니다.
- 성능 저하의 핵심 원인은 질문 내 토큰의 손실 여부이며, 모델이 추론을 요구받는 작업일수록 입력 방식에 따른 성능 격차가 크게 나타납니다.

📖 쉽게 풀어쓴 1분 핵심
사용자가 AI 에이전트와 소통할 때, 키보드로 타이핑하는 것과 음성으로 말하는 것은 모델이 받아들이는 방식에 큰 차이를 만듭니다. 키보드는 오타가 발생해도 모델이 이를 문맥으로 어느 정도 복구하지만, 음성은 변환 도구(STT)가 문장을 재구성하는 과정에서 모델이 이해하기 어려운 구조적 왜곡을 만듭니다. 특히 문제를 풀거나 추론이 필요한 상황에서 이러한 차이는 더욱 두드러지며, 간단한 훈련이나 모델 개선으로도 이 문제를 완벽히 해결하기 어렵다는 점이 확인되었습니다.

🎯 배경 및 문제점
대부분의 LLM은 키보드 타이핑이나 음성 전사를 거친 입력을 처리합니다. 기존 연구들은 단순한 오타나 말하기 습관(추임새)의 영향에 집중해왔으나, 현대의 음성 인터페이스는 단순 전사를 넘어 AI가 내용을 재작성(rewrite)하는 단계를 포함합니다. 본 논문은 이러한 'AI 기반 전사'가 모델 성능에 미치는 비용과 영향을 체계적으로 측정하고자 했습니다.

💡 핵심 기술 및 아키텍처
연구진은 **HIVE(Human Input-Variation Engine)**라는 프레임워크를 개발했습니다.
- **기능:** 음성 전사 변형과 QWERTY 키보드 오타를 생성하여 LLM의 강건성(robustness)을 평가합니다.
- **평가 방식:** 원본 질문을 다양한 음성 스타일과 키보드 오류로 변환한 후, 모델이 이를 얼마나 정확히 이해하고 답변하는지 측정합니다.
- **변형 유형:** 필러(추임새), 망설임, 자기 교정, 구조적 재구성 등을 포함하며, 의미가 훼손되지 않도록 엄격한 규칙 하에 변형을 적용합니다.

📊 실험 결과 분석
- **음성 전사:** 모든 명령어 튜닝 모델에서 정확도 저하가 관찰되었습니다. 성능 저하는 추임새보다 전사의 '구조' 때문입니다.
- **키보드:** 오타는 모델이 상당수 흡수할 수 있어 성능 영향이 적습니다.
- **공통 원인:** 핵심은 '질문의 토큰이 살아남았는가'입니다. 새로운 토큰이 추가되는 것은 비용이 적지만, 원래의 토큰이 파괴될 때 성능이 크게 하락합니다.
- **작업 유형:** 다지선다형 문제에서는 차이가 없으나, 스스로 답을 도출하거나 구성해야 하는 문제에서 입력 방식 간 격차가 발생합니다.
- **대응 한계:** 이 문제는 가벼운 적응 훈련(lightweight adaptation)으로 해결되지 않습니다.
- **생각의 예산(Thinking Budget):** '생각하는 시간/비용'을 늘리면 키보드 입력은 거의 복구되지만, 음성 입력은 여전히 성능 개선이 더디고, 압축된 음성일수록 성능이 더 나빠집니다.

🌍 세상에 미치는 영향 & 실무 적용 사례
- **음성 인터페이스 설계:** LLM 기반 음성 서비스(Siri, Google Assistant, 코딩 에이전트 등)를 개발할 때, AI가 전사 내용을 과도하게 재구성하면 오히려 모델의 추론 능력을 저해할 수 있습니다.
- **실무 가이드:** 복잡한 추론이나 코딩 작업을 수행하는 경우, 음성보다는 키보드 입력이 모델의 성능을 유지하는 데 유리합니다.
- **향후 과제:** STT 및 전사 도구가 LLM의 처리 효율을 고려하여, 중요 정보(토큰)를 보존하는 방향으로 설계되어야 함을 시사합니다.
