같은 질문, 다른 대답: 의미론적 질의 처리에서의 실행 간 변동성

같은 질문, 다른 대답: 의미론적 질의 처리에서의 실행 간 변동성

같은 질문, 다른 대답: 의미론적 질의 처리에서의 실행 간 변동성

> **원본 논문 정보**
> - **제목:** Same Query, Different Answer: Run-to-Run Variance in Semantic Query Processing
> - **저자:** Oktie Hassanzadeh, Dharmashankar Subramanian
> - **발행일:** 2026-10-09
> - **PDF 링크:** [Same Query, Different Answer: Run-to-Run Variance in Semantic Query Processing](https://arxiv.org/pdf/2610.13823v1)


✨ 3줄 핵심 요약
*   거대언어모델(LLM)을 활용한 의미론적 질의 엔진은 온도(temperature)를 0으로 설정해도 실행할 때마다 결과가 달라지는 비결정적 특성을 보입니다.
*   개별 항목의 미세한 결과 변화는 질의 계획(Query Plan)을 거치며 지수적으로 증폭되어 최종 답변의 불일치를 초래합니다.
*   이러한 변동성으로 인해 기존 벤치마크 결과의 신뢰성에 문제가 생기며, 이를 해결하기 위한 새로운 벤치마크 보고 규칙과 엔진 설계 가이드라인이 필요합니다.

📖 쉽게 풀어쓴 1분 핵심
많은 인공지능 기반 데이터베이스 시스템은 '온도 0' 설정을 통해 답변이 항상 똑같을 것이라 가정합니다. 하지만 연구 결과, LLM 기반의 의미론적 연산(필터링, 요약 등)은 매 실행마다 0.07%에서 최대 24%까지 결과값이 바뀝니다. 특히 여러 데이터를 종합해 답변을 내놓는 복잡한 질의에서는 이러한 미세한 변화들이 모여 최종 답변의 약 2/3가 바뀌는 결과를 낳기도 합니다. 즉, 같은 질문을 던져도 시스템이 항상 같은 답변을 보장하지 못한다는 뜻입니다.

🎯 배경 및 문제점
의미론적 질의 엔진은 LLM을 사용해 데이터의 의미를 파악하고 분류하거나 요약합니다. 현재의 벤치마크들은 특정 시스템의 품질을 평가할 때 단 몇 번의 실행 결과만을 토대로 합니다. 그러나 연구자들은 LLM 기반 엔진이 비결정적(nondeterministic)일 수 있다는 점에 주목했습니다. 모델의 배포 방식, 하드웨어 사양 등에 따라 결과가 달라질 수 있는데, 이를 간과하면 시스템의 품질이나 성능 비교 자체가 무의미해질 수 있습니다.

💡 핵심 기술 및 아키텍처
본 연구는 `SemBench`, `LRO-Bench`, `UDA-Bench` 등 주요 벤치마크의 120만 개 모델 호출 로그를 재분석했습니다.
*   **변동성 측정**: 단일 항목에서의 출력 변화율(Flip rate)을 측정.
*   **확률 모델**: 답변이 노출하는 항목 수와 변화율 사이의 관계를 '가능한 세계(possible-worlds)' 모델로 예측.
*   **시스템 평가**: 랭킹, 집계(Aggregation), `LIMIT` 연산이 이러한 변동성을 어떻게 흡수하거나 증폭시키는지 분석.

📊 실험 결과 분석
*   **변동성**: 온도 0에서도 5회 실행 시 약 0.07%~10.2%의 행(row)에서 결과값이 변동하며, 특정 작업에서는 최대 24.0%까지 변화했습니다.
*   **증폭 효과**: 개별 행의 답변 변화는 질의 계획을 거치며 지수적으로 증폭됩니다. 예를 들어, UDA-Bench에서는 추출된 값의 변화는 몇 퍼센트에 불과하지만, 전체 답변의 약 2/3가 영향을 받았습니다.
*   **비결정성**: SemBench에서 게시된 결과 중 21%가 재실행 시 품질 점수가 바뀌었습니다. 결정론적이라고 알려진 엔진에서도 이러한 변화가 관찰되었습니다.

🌍 세상에 미치는 영향 & 실무 적용 사례
*   **벤치마크 지침**: 향후 벤치마크는 단일 실행이 아닌 결과의 분포, 답변 재현율, 실패율 등을 종합적으로 보고해야 합니다.
*   **엔진 설계**: 개발자는 의미론적 질의 결과를 저장할 때 해당 연산의 '결정 마진'이나 '추론 길이'를 함께 기록해야 합니다.
*   **실무적 조언**: 답변을 재현해야 할 경우, 모델을 재호출하는 대신 이전에 기록된 연산 결과를 재사용하는 것이 권장됩니다. 투표(Voting) 방식은 변동성을 줄일 수는 있으나 완벽히 제거하지는 못하므로, 중요한 항목에 자원을 집중하는 전략이 필요합니다.
