> **원본 논문 정보**
> - **제목:** OctoLong: Mid-Training On Cross-Repository Code Contexts Enhances Long-Context Modeling
> - **저자:** Indraneil Paul, Falko Helm, Goran Glavaš, Iryna Gurevych
> - **발행일:** 2026-08-05
> - **PDF 링크:** [OctoLong: Mid-Training On Cross-Repository Code Contexts Enhances Long-Context Modeling](https://arxiv.org/pdf/2608.05141v1)


✨ 3줄 핵심 요약
- **OctoLong**은 AST 파서와 언어 서버를 활용해 저장소 경계를 넘나드는 다중 홉(multi-hop) 의존성 코드 데이터를 구축하는 새로운 파이프라인입니다.
- 기존 문맥 확장 데이터를 약 12%만 대체해도 장거리 정보 검색, 코드 이해 및 에이전트 작업 수행 능력이 실질적으로 향상되었습니다.
- 이를 통해 학습된 **OctoLong-Instruct** 모델군(600M~14B 파라미터)은 다양한 벤치마크에서 기존의 강력한 오픈 가중치 모델들을 능가하는 성능을 보였습니다.

📖 쉽게 풀어쓴 1분 핵심
기존의 장문 문맥 언어 모델들은 주로 책이나 일반적인 문서를 학습 데이터로 사용했는데, 이는 코드처럼 복잡하게 얽힌 정보(의존성)를 학습하기엔 부족했습니다. OctoLong은 코드의 논리적 구조를 분석하여 관련 있는 코드 조각들을 수백만 토큰 단위로 연결해 학습시킵니다. 마치 프로그래머가 여러 파일에 흩어진 코드를 따라가며 이해하듯, 모델이 코드 간의 관계를 깊이 있게 학습하게 함으로써 코딩 업무와 에이전트 작업에서 훨씬 뛰어난 성능을 발휘하게 만들었습니다.

🎯 배경 및 문제점
- **데이터의 한계:** 기존 장문 모델용 학습 데이터는 코드 저장소의 의존성을 충분히 반영하지 못하며, 관련 없는 정보를 포함하거나 복잡한 다중 홉 의존성이 결여된 경우가 많습니다.
- **아키텍처의 한계:** 희소(Sparse) 또는 선형(Linear) 어텐션과 같은 아키텍처적 시도는 단독 사용 시 긴 문맥에서 성능 저하를 겪어, 데이터 엔지니어링을 통한 해결이 더욱 중요해졌습니다.

💡 핵심 기술 및 아키텍처
- **OctoLong 파이프라인:** AST(추상 구문 트리) 파서, LSP(언어 서버 프로토콜) 백엔드, 패키지 매니저를 통합하여 저장소 간의 코드 참조를 재귀적으로 검색합니다.
- **데이터 구축:** 이를 통해 의존성이 풍부한 방대한 코드 문맥을 생성합니다.
- **학습 전략:** 기존 베이스 모델에 약 50B 토큰 규모의 혼합 데이터를 추가 학습(Mid-training)시켰으며, 그중 약 6.2B 토큰은 OctoLong 방식으로 생성된 코드 문맥입니다. 이후 약 10B 토큰의 명령어 튜닝을 거쳤습니다.

📊 실험 결과 분석
- **성능 향상:** 18개의 오픈 가중치 모델과 비교했을 때, OctoLong-Instruct는 긴 문맥에서의 정보 검색, 상태 추적, 저장소 단위의 코드 이해에서 높은 성과를 거뒀습니다.
- **범용성:** 장문 문맥 작업뿐만 아니라, 짧은 문맥의 코딩 시나리오에서도 API 활용 능력이 향상되었습니다.
- **기여도:** 기존 학습 데이터의 12%를 OctoLong 데이터로 교체하는 것만으로도 성능이 크게 개선됨을 확인했습니다(실험 수치는 논문 내 표 8, 9 참조).

🌍 세상에 미치는 영향 & 실무 적용 사례
- **소프트웨어 개발 효율화:** 거대 저장소 전체를 문맥으로 이해해야 하는 코드 유지보수나 복잡한 버그 수정 등 에이전트 기반 작업에서 모델의 활용도가 크게 높아질 것입니다.
- **실무 적용:** IDE 내 AI 코딩 도구, 복잡한 프로젝트 아키텍처 분석, 다중 파일 참조가 필요한 자동화 도구 개발 등에 직접적인 성능 개선을 제공합니다.
