LLM 개발 에이전트 간의 명세서 이식성: 명세 기반 소프트웨어 마이그레이션에서의 에이전트 간 호환성

> **원본 논문 정보**
> - **제목:** Specification Portability Across LLM Development Agents: Cross-Agent Compatibility in Specification-Driven Software Migration
> - **저자:** Oleg Grynets, Oleksii Ilchuk, Dariia Zatulna, Vasyl Lyashkevych
> - **발행일:** 2026-08-21
> - **PDF 링크:** [Specification Portability Across LLM Development Agents: Cross-Agent Compatibility in Specification-Driven Software Migration](https://arxiv.org/pdf/2608.21208v1)


✨ 3줄 핵심 요약
* LLM 에이전트가 작성한 소프트웨어 명세서는 다른 에이전트가 재사용할 때 성능 저하가 발생할 수 있는 '비이식적'인 결과물입니다.
* 명세서의 길이는 구현 품질을 예측하는 지표가 되지 않으며, 에이전트마다 적합한 명세 해석 방식이 다릅니다.
* 검색 증강 생성(RAG) 기반의 명세 주입 방식이 서로 다른 에이전트 간의 호환성을 보완하는 가장 효과적인 전략으로 확인되었습니다.

📖 쉽게 풀어쓴 1분 핵심
최근 AI가 소프트웨어 개발의 중추 역할을 하면서, AI가 만든 설계도(명세서)를 다른 AI에게 전달해 작업을 이어가는 경우가 많아졌습니다. 본 논문은 과연 A라는 AI가 쓴 설계도를 B라는 AI가 그대로 이해하고 잘 실행할 수 있는지 검증했습니다. 실험 결과, 설계도를 건네받은 AI의 성능이 크게 떨어지는 경우가 빈번했습니다. 즉, 설계도는 AI마다 '언어'가 다르기 때문에 범용적으로 쓸 수 없으며, 이를 해결하기 위해 단순 요약보다는 검색 기반의 정보 주입(RAG) 전략을 활용해야 한다는 점을 밝혀냈습니다.

🎯 배경 및 문제점
LLM 기반의 개발 방식은 명세서가 곧 구현으로 이어지는 '명세 기반 개발(SDD)'로 진화하고 있습니다. 하지만 기존 방식은 특정 에이전트 내에서만 명세와 구현이 완결되는 것을 전제로 합니다. 저자들은 이 명세서가 과연 다른 환경의 에이전트로 이동했을 때에도 품질 유지(이식성)가 가능한지 의문을 제기했습니다. 특히, 에이전트 간의 호환성이 대칭적이지 않고 방향성을 가진다는 점이 핵심적인 기술적 과제로 떠올랐습니다.

💡 핵심 기술 및 아키텍처
연구진은 Oracle DB에서 PostgreSQL 16으로 데이터를 마이그레이션하는 과제를 통해 명세서 이식성을 측정했습니다.
* **평가 지표:** Token F1, SQL 구문 유효성, AST(추상 구문 트리) 유사도, 실행 가능성 등 다차원 지표를 정의했습니다.
* **적응 전략:** 명세서의 품질 저하를 막기 위해 '재작성(Rewrite)', '압축(Compression)', '검색 증강 주입(Retrieval-augmented ingestion)' 세 가지 방식을 도입하여 에이전트 간 호환성을 테스트했습니다.

📊 실험 결과 분석
* **이식성 부족:** Gemini가 Kiro 에이전트가 생성한 명세서를 그대로 소비했을 때, Token F1 0.035, SQL 구문 유효성 2.33%, AST 유사도 0.015라는 매우 낮은 품질을 기록했습니다.
* **전략의 효율성:** '압축'은 범용적인 이익을 주지 못했고, '재작성'은 특정 환경에서 개선 효과가 있었으나, '검색 증강 주입' 방식만이 여러 에이전트(Gemini, Copilot 등)에서 일관된 성능 향상을 보인 유일한 전략이었습니다.
* **데이터:** 1,006개의 PL/SQL 파일을 이용한 1단계 테스트와 1,802개의 스크립트 기반 2단계 실험을 수행했습니다.

🌍 세상에 미치는 영향 & 실무 적용 사례
다중 에이전트 시스템을 구축하는 기업들은 이제 명세서를 '범용적인 문서'로 취급해서는 안 됩니다. 명세서를 작성한 에이전트와 구현하는 에이전트가 다를 경우 반드시 중간 단계에서 재작성이나 RAG 기반의 해석 보정 과정을 거쳐야 합니다. 이 연구는 향후 복잡한 소프트웨어 공학 파이프라인에서 AI 에이전트 간의 원활한 협업을 위한 표준화된 '명세서 이식성 프로토콜'의 필요성을 강조합니다.
