소프트웨어 및 시스템 보안을 위한 LLM 기반 에이전트: 접근 방식, 응용 및 평가

> **원본 논문 정보**
> - **제목:** LLM-Based Agents for Software and Systems Security: Approaches, Applications, and Assessment
> - **저자:** Jingjing Nie, Jiawei Guo, Krishna Meda, Haipeng Cai
> - **발행일:** 2026-08-28
> - **PDF 링크:** [LLM-Based Agents for Software and Systems Security: Approaches, Applications, and Assessment](https://arxiv.org/pdf/2608.28490v1)


✨ 3줄 핵심 요약
- 2023년부터 2026년까지 발표된 100편의 동료 심사 논문을 체계적으로 분석하여 보안 에이전트의 기술적 현주소를 조명했습니다.
- 보안 에이전트 개발은 공격적·수행적 기능에 집중되어 있으나, 행동의 제약(bounded authority) 및 감사 가능성(auditable)은 매우 부족한 실정입니다.
- 보안 에이전트를 단순히 LLM 프롬프트가 아닌, 운영 체제적 관점에서 접근하고 인간의 감독과 안전 장치를 강화할 필요가 있음을 제언합니다.

📖 쉽게 풀어쓴 1분 핵심
최근 보안 분야에서는 복잡한 보안 업무를 수행하기 위해 계획을 세우고 도구를 사용하는 'LLM 기반 에이전트' 도입이 급증하고 있습니다. 연구진은 지난 4년간의 학술 문헌을 분석한 결과, 현재 개발된 에이전트들이 정보를 수집하고 공격을 시도하는 등 '행동 능력'은 뛰어나지만, 정작 중요한 '보안 통제'와 '과정 투명성'은 놓치고 있음을 발견했습니다. 이제는 에이전트가 어떤 의사결정을 내렸는지 인간이 검증하고, 행동 범위를 스스로 제한할 수 있는 실질적인 운영 체제로서의 발전이 필요하다는 지적입니다.

🎯 배경 및 문제점
- **보안 업무의 특성:** 소스 코드, 로그, 정책 등 이질적인 데이터를 다루고 가설 검증, 도구 호출, 계획 수정이 반복되는 절차적 업무로 LLM 활용도가 높음.
- **분야의 혼란:** '에이전트'라는 용어가 일관성 없이 사용되고 있으며, 응용 분야별 위험도 차이가 크고 평가 방식이 제각각이라 비교가 어려움.
- **기술적 편향성:** 시스템을 '수행'하게 만드는 데는 치중했으나, 권한을 제한하거나 행동을 감사(Audit)할 수 있는 구조적 설계가 미흡함.

💡 핵심 기술 및 아키텍처
- **에이전트 구성:** 대부분(91%)이 모듈형 파이프라인을 채택하며, 88%의 시스템이 LLM을 '계획자(Planner)'이자 '행동자(Actor)'로 활용함.
- **주요 응용 사례:** 취약점 식별, 침투 테스트(Pentest), 보안 패치 생성, CTF 문제 해결 등에 집중됨.
- **부족한 안전 장치:** 비판자(Critic)나 검증자(Verifier) 역할을 포함하는 시스템은 15%, 안전 가이드라인(Guardrail) 층은 13%, 인간 검토 절차는 13%에 불과함.

📊 실험 결과 분석
- **평가의 불균형:** 성공률(51%)이나 정밀도/재현율(34%) 같은 결과 중심 측정은 흔하지만, 환각 발생률(11%), 도구 사용 정확도(1%) 등 과정의 신뢰성을 확인하는 지표는 매우 낮음.
- **응용의 불균형:** 취약점 분석이나 초기 침입 단계에 연구가 집중된 반면, 권한 상승 이후의 측면 이동(Lateral movement)이나 데이터 유출, 시스템 유지 관리 등은 연구가 부족함.
- **비교의 어려움:** 논문마다 사용하는 도구, 환경, 예산 등이 달라 직접적인 성능 비교가 불가능한 환경임.

🌍 세상에 미치는 영향 & 실무 적용 사례
- **향후 연구 방향:** 보안 에이전트를 단순 모델이 아닌 '운영 시스템'으로 인식해야 함. 향후 연구는 결과값뿐만 아니라 공정성, 안전성, 비용, 인간 감독 기능을 결합하는 통합 설계에 집중되어야 함.
- **실무적 교훈:** 보안 자동화 시스템 도입 시, 에이전트가 어떤 근거로 도구를 호출하고 의사결정을 내리는지 추적 가능한 '감사 가능성' 확보가 필수적임.
- **발전 과제:** 초기 침입 외에도 실무에서 요구되는 복합적인 보안 단계(데이터 유출 방지, 권한 관리 등)를 수행할 수 있는 보다 성숙한 보안 에이전트 아키텍처 구축이 필요함.
