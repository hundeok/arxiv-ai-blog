올바르게 읽고 잘못 행동하기: 에이전트 루프에서 시스템 1 모델의 의사결정 실패 진단

> **원본 논문 정보**
> - **제목:** Reading Right, Acting Wrong: Diagnosing Decision Failures of System One Models in Agent Loops
> - **저자:** Yubo Li, Ramayya Krishnan, Rema Padman
> - **발행일:** 2026-10-13
> - **PDF 링크:** [Reading Right, Acting Wrong: Diagnosing Decision Failures of System One Models in Agent Loops](https://arxiv.org/pdf/2610.18579v1)


✨ 3줄 핵심 요약
- '시스템 1' 모델은 의사결정 과정에서 추론 흔적(Chain of Thought)을 남기지 않아 오류 원인 파악이 어렵습니다.
- 연구 결과, 우수한 모델일수록 정보를 정확히 읽고도 잘못된 행동을 선택하는 '읽기 올바름, 행동 잘못됨' 현상이 빈번합니다.
- 모델의 읽기 능력과 결정 능력을 별도로 측정하여, 결정 단계에만 코드나 계획 도구를 결합하는 방식이 에이전트 설계의 핵심임을 확인했습니다.

📖 쉽게 풀어쓴 1분 핵심
빠르고 저렴한 비용으로 작동하는 '시스템 1' 인공지능 모델들은 정보를 한 번에 읽고 즉시 결과를 내놓습니다. 하지만 이들이 잘못된 행동을 할 때, 과연 정보를 잘못 이해한 것인지(읽기 실패), 아니면 정보는 제대로 알았는데 판단을 잘못한 것인지(결정 실패)를 알 수 없었습니다. 본 연구는 모델에게 환경 상태에 관한 구체적인 질문(프로브)을 따로 던져, 정보 이해력과 의사결정력을 분리 평가했습니다. 분석 결과, 성능이 뛰어난 모델조차 정보를 정확히 파악하고도 이를 논리적으로 조합해 올바른 행동으로 연결하지 못하는 문제가 공통적으로 발견되었습니다.

🎯 배경 및 문제점
- **시스템 1 모델의 특징:** 문장을 생성하지 않고 선택지 중 하나를 확률적으로 골라내어 속도가 매우 빠르지만, 내부 작동 과정을 추적할 수 없는 '블랙박스' 구조입니다.
- **진단 난제:** 최종 행동이 틀렸을 때, 그것이 정보 인지 오류인지 의사결정 알고리즘 오류인지 구분할 방법이 부족했습니다.
- **연구 질문:** 행동을 유도하는 '정보 파악'과 최종적인 '행동 결정' 능력을 분리하여 측정하고, 그 실패의 원인을 행동적 관점에서 분석하고자 했습니다.

💡 핵심 기술 및 아키텍처
- **행동 기반 진단:** 모델이 환경 상태를 보고 행동을 결정할 때, 동시에 해당 상태와 관련된 사실 확인 질문(Factual probes)을 수행하여 일치 여부를 대조했습니다.
- **벤치마크 구성:** 시뮬레이터(ALFWorld 등), 고객 서비스 정책, 웹 내비게이션, 코딩 등 65,228개의 기록으로 구성된 고정 벤치마크를 활용했습니다.
- **진단 방법론:** 
    - **조합 사다리(Composition ladder):** 모델이 사실은 알고 있으나 이를 행동으로 결합하는 데 실패하는지 확인.
    - **프로브 후 결정(Probe-then-decide):** 사실 정보를 명시적으로 제공했을 때 행동 오류가 교정되는지 측정.

📊 실험 결과 분석
- **읽기 vs 결정:** 테스트한 17개의 시스템과 1개의 추론 모델 모두에서, 잘못된 행동의 대부분은 정보를 정확히 읽은 후에 발생했습니다.
- **오류의 집중:** 시스템의 종류와 무관하게 특정 상태에서 오류가 반복적으로 발생하는 패턴이 관찰되었습니다.
- **결정력의 공백:** 결정적인 사실들을 충분히 제공받은 상태에서도 모델이 이를 조합하지 못하는 경우가 많았습니다. 코드 등을 통해 모델이 직접 답한 사실들을 다시 입력해주자 상당수의 실패가 복구되었습니다.
- **추가 발견:** 복잡한 작업에서는 단순히 정보가 부족한 것이 아니라, '다음 하위 목표(sub-goal)'를 설정하는 능력이 부족함이 드러났습니다.

🌍 세상에 미치는 영향 & 실무 적용 사례
- **에이전트 설계 전략:** 모델이 스스로 모든 것을 판단하게 하기보다, 모델은 '읽기'에 집중하게 하고, 결정 조합은 코드나 계획 엔진(Planner)에게 맡기는 하이브리드 설계가 필요함을 시사합니다.
- **신뢰성 검증:** 단순히 최종 정확도 지표에 의존하는 대신, 특정 상태별로 읽기 능력과 결정 능력을 별도로 측정하는 진단 패널을 도입해야 합니다.
- **비용 효율적 모델 활용:** 모든 상태에 무거운 추론 모델을 쓰는 대신, 어떤 상태에서 빠른 모델을 믿고 어떤 상태에서 깊은 숙고가 필요한지 구분하는 기준을 마련하는 데 본 연구의 진단 도구가 활용될 수 있습니다.
