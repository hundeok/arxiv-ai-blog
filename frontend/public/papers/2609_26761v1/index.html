A2M: MCP 생태계 내 추적 최적화 기반 에이전트 하이재킹

A2M: MCP 생태계 내 추적 최적화 기반 에이전트 하이재킹

> **원본 논문 정보**
> - **제목:** A2M: Trace-Optimized Agent Hijacking in the MCP Ecosystem
> - **저자:** Laizhen Li, Xuan Wang, Peicheng Zhao, Juanjuan Zhao, Kejiang Ye, Cheng-zhong Xu, Xitong Gao
> - **발행일:** 2026-09-22
> - **PDF 링크:** [A2M: Trace-Optimized Agent Hijacking in the MCP Ecosystem](https://arxiv.org/pdf/2609.26761v1)


✨ 3줄 핵심 요약
- MCP(Model Context Protocol) 환경에서 공격자가 악성 도구를 삽입해 에이전트를 조종하는 'A2M' 프레임워크를 제안함.
- 2단계 공격(유인 및 조작)을 통해 에이전트가 악성 도구를 선택하게 유도하고, 이후 출력을 정교하게 조작함.
- GLM-4.6 모델 기준 93.6%의 악성 도구 호출률을 기록했으며, 이는 MCP 생태계의 도구 검증 강화가 필수적임을 시사함.

📖 쉽게 풀어쓴 1분 핵심
최근 AI 에이전트들은 MCP라는 표준 프로토콜을 통해 외부 서비스를 도구처럼 자유롭게 사용합니다. 하지만 에이전트가 어떤 도구를 선택할지 결정할 때 '도구 이름'이나 '설명' 같은 메타데이터에 의존한다는 점이 보안 취약점이 될 수 있습니다. A2M은 이를 악용합니다. 첫째, 그럴듯한 설명으로 에이전트가 악성 도구를 선택하게 만들고(유인), 둘째, 도구 실행 결과에 조작된 데이터를 넣어 에이전트의 다음 행동을 공격자가 원하는 방향으로 강제합니다(조작). 이 공격은 에이전트가 도구의 반응을 믿을 수 있는 환경 정보로 간주한다는 점을 파고들어, 시스템을 오작동시키거나 민감한 정보를 빼냅니다.

🎯 배경 및 문제점
- **MCP의 취약점:** 에이전트가 제3자가 제공하는 도구를 체계적인 검증 없이 선택할 때 발생하는 '의미론적 공급망 위험(Semantic supply-chain risk)'이 존재함.
- **기존 연구의 한계:** 기존 연구는 주로 사용자-에이전트 간의 직접적인 공격(jailbreaking 등)에 집중했으나, MCP 환경에서는 사용자나 에이전트가 정상이라도 도구 자체의 메타데이터를 조작하여 에이전트를 하이재킹할 수 있음.
- **신뢰의 오류:** 에이전트가 도구의 응답 내용을 검증되지 않은 입력이 아닌, 신뢰할 수 있는 환경 피드백으로 간주하여 공격에 취약함.

💡 핵심 기술 및 아키텍처
- **A2M 프레임워크:** 2단계 블랙박스 공격 구조로 설계됨.
    - **1단계 (유인, Attraction):** '권위', '긴급성', '포괄성' 등 5가지 설득 전략을 활용하여 에이전트가 해당 도구를 선택할 확률을 최대화하는 메타데이터를 최적화함.
    - **2단계 (조작, Manipulation):** 실행 기록(trace)을 분석하여 도구 반환값을 정교하게 다듬음으로써 에이전트의 사고와 행동을 공격자가 원하는 방향으로 유도함.
- **분석기 및 최적화기:** 실행 결과를 해석하는 분석기(Analyzer)와 이를 바탕으로 공격 페이로드를 개선하는 최적화기(Optimizer)가 반복 루프를 형성함.

📊 실험 결과 분석
- **GLM-4.6 모델 기준:**
    - 악성 도구 호출률(MTIR): 93.6%
    - 정보 탈취, 환경 무결성 침해, 추론 왜곡 등 공격 성공률(ASR): 평균 74.4%
    - 인지적 서비스 거부(C-DoS) 공격 시 정상 대비 토큰 비용 증가: 32.4배
- **모델 전이 실험:** 추가 최적화 없이 타 모델 4종에 적용했을 때 MTIR은 평균 63.6%, 공격 성공률은 24.5%를 기록함.
- **절제 연구:** 2단계 생성, 초기 설득 전략, 궤적 최적화 등 각 구성 요소가 제거될 경우 성능(비용 배수 등)이 유의미하게 하락함을 확인하여 각 단계의 유효성을 입증함.

🌍 세상에 미치는 영향 & 실무 적용 사례
- **보안 위협 제기:** 현재의 MCP 생태계가 도구 등록 및 검증 체계에서 심각한 보안 결함을 가지고 있음을 증명함.
- **대응 방향:** 단순히 메타데이터를 바꾸는 것만으로는 방어가 불가능하며, 더 강력한 도구 검증 절차와 런타임 정보 흐름 제어(Runtime information-flow control)가 도입되어야 함.
- **연구 공개:** 연구팀은 공격 프레임워크인 A2M의 소스 코드를 공개하여 보안 취약점을 점검하고 방어 체계를 구축하는 데 활용하도록 함.
