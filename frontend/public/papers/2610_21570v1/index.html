하드웨어 설계를 위한 LLM 기반 기능 커버리지 완성을 위한 독립적 데이터 무결성 검증

하드웨어 설계를 위한 LLM 기반 기능 커버리지 완성을 위한 독립적 데이터 무결성 검증

하드웨어 설계를 위한 LLM 기반 기능 커버리지 완성을 위한 독립적 데이터 무결성 검증

> **원본 논문 정보**
> - **제목:** Independent Data-Integrity Verification for LLM-Driven Functional Coverage Closure in Hardware Design
> - **저자:** Venkata Krishna Kumar Vedantam
> - **발행일:** 2026-10-15
> - **PDF 링크:** [Independent Data-Integrity Verification for LLM-Driven Functional Coverage Closure in Hardware Design](https://arxiv.org/pdf/2610.21570v1)


✨ 3줄 핵심 요약
* 하드웨어 설계 검증 시 LLM이 생성한 테스트 코드는 커버리지 달성 여부와 별개로 데이터 무결성을 보장하지 않는다는 문제에 주목했습니다.
* 커버리지 보고서와 데이터 검증용 스코어보드를 LLM의 외부에서 독립적으로 운영하는 자동화 에이전트 아키텍처를 제안했습니다.
* 비동기 FIFO, UART, AHB2APB 등 3종의 설계에서 8번의 반복 내에 모든 커버리지를 100% 달성하는 성과를 보였습니다.

📖 쉽게 풀어쓴 1분 핵심
하드웨어 설계 검증 과정에서 LLM(거대언어모델)을 사용해 커버리지(테스트 완료 범위)를 높이는 시도가 늘고 있습니다. 하지만 LLM이 짠 테스트 코드가 단순히 '해당 상태에 도달했다'고 해서 그 과정의 데이터 흐름까지 올바르다고 단정할 수는 없습니다. 이 논문은 LLM이 생성한 테스트를 그대로 믿지 않고, 시뮬레이터가 직접 뱉어내는 커버리지 보고서와 별도의 데이터 검증 장치(스코어보드)를 사용하여, 커버리지 달성 여부와 데이터의 정확성을 분리하여 검증하는 시스템을 제안합니다.

🎯 배경 및 문제점
- **커버리지와 데이터 무결성의 차이:** 기존 방식은 커버리지 확보에만 집중하여, 정작 데이터 경로의 오류를 잡아내지 못하는 한계가 있었습니다.
- **LLM 신뢰도 부족:** LLM이 생성한 테스트 자극(stimulus)은 그 자체로 올바르다는 보장이 없으며, 기존 연구에 따르면 모델이 생성한 자극이 골든 레퍼런스를 통과하는 비율은 15.7~21.7% 수준에 불과합니다.
- **기존 방식의 한계:** 커버리지 달성 확인 과정에 LLM 자신의 보고를 신뢰하는 경우가 많아, 독립적인 외부 검증 체계가 필수적입니다.

💡 핵심 기술 및 아키텍처
- **독립적 검증 루프:** LLM은 RTL 코드와 타겟 커버리지 빈(bin) 정보를 받아 테스트를 생성합니다. 이때 커버리지는 시뮬레이터의 출력 파일(YAML)에서 직접 읽어오며, LLM의 주장과는 분리됩니다.
- **단일 빈 타겟팅:** 전체를 한 번에 커버하려 하지 않고, 해결되지 않은 특정 빈 하나를 목표로 프롬프트를 구성하여 모델의 집중력을 높입니다.
- **데이터 무결성 확인:** 테스트가 수행된 후, 독립적인 결정론적 스코어보드를 통해 데이터 오류 여부를 판단합니다.
- **반응형 모니터:** FIFO 설계의 경우, 별도의 모니터를 통해 테스트 중 실시간으로 데이터 무결성을 감시합니다.

📊 실험 결과 분석
- **커버리지 달성:** 비동기 FIFO(91.7%→100%), UART(88.9%→100%), AHB2APB(67.4%→100%) 설계 모두에서 8번의 반복 수행 내에 100% 커버리지를 달성했습니다.
- **버그 검출:** 반응형 모니터를 통해 저자 본인의 테스트 벤치 코드에 있던 클럭 도메인 교차(CDC) 버그를 발견했습니다.
- **한계점:** 논문에서는 실험 설계의 제한사항(3개의 작은 설계, 대조군 부재, 절제 연구 미실시 등)을 명시하며, LLM이 생성한 테스트의 데이터 무결성이 모든 루프에서 완전히 검증되지는 않았음을 인정했습니다.

🌍 세상에 미치는 영향 & 실무 적용 사례
이 연구는 LLM을 활용한 반도체 검증 자동화가 '생성'에서 나아가 '독립적 검증'으로 진화해야 함을 시사합니다. 특히 하드웨어 설계와 같이 데이터 정확도가 절대적인 분야에서, 모델의 출력을 비판적으로 검증하는 아키텍처를 도입함으로써 LLM 기반 설계 검증 도구의 실무 적용 가능성을 한 단계 높였습니다. 향후 모니터링 기능을 생성된 모든 테스트에 적용한다면, 더욱 정교한 자동 검증 시스템 구축이 가능할 것으로 전망됩니다.
