# LLM은 런타임 동작을 추론할 수 있는가? 저장소 수준의 동적 벤치마크

> **원본 논문 정보**
> - **제목:** Can LLMs Reason About Runtime Behavior? A Repository-Level Dynamic Benchmark
> - **저자:** Hamed Taherkhani, Mohammad Abdollahi, Melika Sepidband, Hridya Dhulipala, Tien N. Nguyen, Hadi Hemmati
> - **발행일:** 2026-09-23
> - **PDF 링크:** [Can LLMs Reason About Runtime Behavior? A Repository-Level Dynamic Benchmark](https://arxiv.org/pdf/2609.28449v1)


## ✨ 3줄 핵심 요약
- 코드 실행 시 발생하는 런타임 동작을 추론하는 LLM의 능력을 평가하는 저장소 수준의 벤치마크 'SWE-FLUX'를 제안함.
- 12개의 실제 파이썬 저장소에서 추출한 480개의 실행 기반 사례를 통해 검증한 결과, 최고 성능 모델도 37.71%의 정확도에 그침.
- 데이터 흐름, 인터-프로시저(함수 간) 실행, 상태 추론 및 다중 테스트 집계 등 복합적인 동적 추론 작업에서 모델들이 큰 어려움을 겪음.

## 📖 쉽게 풀어쓴 1분 핵심
대규모 언어 모델(LLM)은 코드를 작성하는 데는 능숙하지만, 작성된 코드가 실제로 실행될 때 어떤 흐름으로 동작하는지 이해하는 능력은 부족합니다. 기존 연구들은 단순한 코드 조각을 대상으로 하거나 정적인 코드 이해에 머물러 있었습니다. 본 논문은 실제 저장소 단위에서 코드가 실행될 때 발생하는 제어 흐름, 데이터 변화, 예외 상황 등을 얼마나 정확히 추론하는지 평가합니다. 연구 결과, LLM은 코드의 표면적인 의미는 파악할 수 있지만, 복잡하게 얽힌 실제 실행 과정에서의 상태 변화를 추적하는 데는 아직 한계가 명확함이 드러났습니다.

## 🎯 배경 및 문제점
- **런타임 동작의 중요성:** 디버깅, 보안 분석, 변경 영향 분석 등 소프트웨어 엔지니어링의 핵심 업무는 소스 코드에 암묵적으로 내재된 런타임 동작(실행 경로, 중간 상태 등)을 이해해야 함.
- **기존 벤치마크의 한계:** 대부분의 기존 벤치마크는 단일 함수나 짧은 코드 조각에 국한되어 있으며, 저장소 수준의 복잡한 실행 맥락을 다루지 못함.
- **정적 분석의 한계:** 실행 환경이 없거나 접근이 제한된 상황에서 LLM은 소스 코드만 보고 실제 동작을 추론해야 하지만, 이는 매우 고난도의 작업임.

## 💡 핵심 기술 및 아키텍처
- **SWE-FLUX 벤치마크:** 480개의 실행 기반(execution-grounded) 사례를 포함하며, 정답은 사람이 작성하거나 LLM이 판단하는 대신, 계측된 테스트 실행 로그에서 자동으로 추출함.
- **오라클 수확 파이프라인(Oracle Harvesting Pipeline):** 
    - 실행 환경을 격리하여 테스트를 수행하고, 트레이싱 훅을 통해 실행된 라인, 함수 호출, 변수 스냅샷 등을 기록.
    - 파서를 통해 실행 추적(trace)에서 직접 정답을 생성하여 주관적 판단 오류를 배제.
- **입력 섭동(Input Perturbation):** 기존 사례에 입력을 변화시켜 더 도전적인 문제 변형을 생성하고 벤치마크의 확장성을 확보.

## 📊 실험 결과 분석
- **모델 성능:** 5개의 LLM을 평가한 결과, 최고 모델의 정확도는 37.71%에 불과함.
- **강점:** 불변성(invariants), 프로시저 내 제어 흐름, 예외 처리, 단순 반복문 등 국소적인 동작 추론에서는 상대적으로 나은 성능을 보임.
- **약점:** 데이터 흐름(dataflow), 함수 간 실행 추적, 정밀한 상태 추론, 다중 테스트 결과 종합(suite-level aggregation) 등에서 심각한 오류가 발생함.
- **오류 패턴:** 모델들이 실제 실행 결과보다 소스 코드상으로 그럴듯해 보이는 '정적 편향'에 의존하는 경향이 확인됨.

## 🌍 세상에 미치는 영향 & 실무 적용 사례
- **개발 도구의 고도화:** 이 벤치마크는 버그 자동 수정 및 코드 리뷰 도구가 실제 실행 동작을 바탕으로 판단할 수 있도록 모델의 역량을 측정하는 지표가 됨.
- **기술적 제언:** LLM이 단순 텍스트 처리를 넘어 동적 분석 도구(트레이스 로그, 정적 def-use 그래프 등)와 결합된 '하이브리드 시스템'으로 진화해야 함을 시사함.
- **학습 방법론:** 모델이 단순한 텍스트 답변이 아닌 '실행 기반의 충실한 예측'을 하도록 최적화하는 새로운 학습 방향을 제시함.
