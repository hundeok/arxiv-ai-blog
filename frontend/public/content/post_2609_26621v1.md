# 탐욕적 디코딩은 정밀도 불변이 아니다: 거대언어모델 추론에서의 교차 정밀도 출력 발산

> **원본 논문 정보**
> - **제목:** Greedy Decoding Is Not Precision-Invariant: Cross-Precision Output Divergence in LLM Inference
> - **저자:** Gaoyuan Du, Anam Nawaz Khan, Rex Zhou, Xiaoyang Liu, Deepayan Chakrabarti, Fnu Suya, Xueping Li
> - **발행일:** 2026-09-22
> - **PDF 링크:** [Greedy Decoding Is Not Precision-Invariant: Cross-Precision Output Divergence in LLM Inference](https://arxiv.org/pdf/2609.26621v1)


## ✨ 3줄 핵심 요약
*   동일한 하드웨어와 모델이라도 BF16과 FP16 등 사용하는 수치 정밀도에 따라 탐욕적 디코딩(Greedy Decoding)의 결과값이 달라지는 현상이 확인되었습니다.
*   이러한 발산은 주로 모델 출력층(lm_head)의 로짓 마진(logit margin) 차이에서 기인하며, 토큰 단위에서는 높은 발산율을 보이나 실제 작업 수행 결과(코드 실행 등)의 정합성은 상대적으로 높게 유지됩니다.
*   발산이 예측되는 특정 구간에서만 선택적으로 FP32 재계산을 수행하는 기법을 통해, 4% 미만의 지연 시간 오버헤드로 높은 정밀도 간 일치율을 확보할 수 있습니다.

## 📖 쉽게 풀어쓴 1분 핵심
우리는 거대언어모델(LLM)이 같은 질문에 항상 같은 답을 내놓을 것이라 기대하지만, 실제로는 계산할 때 사용하는 데이터 형식(BF16, FP16 등)에 따라 결과가 바뀝니다. 논문은 이 현상이 정밀도 차이에 따른 미세한 오차 때문임을 밝히고, 모델이 다음 토큰을 선택할 때 가장 확률이 높은 두 후보 간의 차이가 작을 때만 해당 단계에서 정밀도를 높여 재계산하는 방식을 제안합니다. 이 방법은 전체 과정을 정밀하게 계산하는 것보다 훨씬 효율적이면서도 모델의 결과물 일치도를 크게 높여줍니다.

## 🎯 배경 및 문제점
*   **결정론적 가정의 오류:** 탐욕적 디코딩은 이론상 결정론적이지만, 실제로는 서로 다른 정밀도(Precision) 간 출력이 일치하지 않는 '정밀도 불변성 미준수' 문제가 발생합니다.
*   **실무적 위험:** 정밀도에 따른 출력 드리프트(drift)는 모델 평가의 신뢰성을 떨어뜨리고, 오차 추적(auditing)이나 재현성을 보장하기 어렵게 만듭니다.
*   **범위:** 1.1B부터 7B 매개변수 모델 및 12B 모델까지 평가한 결과, 49~100%의 프롬프트에서 출력 발산이 확인되었습니다.

## 💡 핵심 기술 및 아키텍처
*   **오차 전파 분석:** 출력 발산이 모델의 마지막 출력층(lm_head)에서 상위 두 로짓(logit) 사이의 마진과 관련이 깊다는 것을 발견했습니다.
*   **선택적 FP32 재계산 (Intervention C):** 모든 단계를 FP32로 계산하지 않고, 로짓 마진이 특정 임계값 이하로 떨어지는 위험 구간에서만 출력층의 연산을 FP32로 수행하여 오차를 보정합니다.
*   **제약 사항:** 이 방법은 모델 내부 본체(body)에서 발생하는 오차가 지배적인 경우(예: 배치가 8 이상이거나 FP8 환경)에는 효과가 감소하는 부분적인 보완책입니다.

## 📊 실험 결과 분석
*   **일치율 향상:** 이 기법 적용 시 A10G 환경에서 22~36%p, L4 및 A100 환경에서 12~21%p의 출력 일치율 상승을 기록했습니다.
*   **실제 성능:** HumanEval 코드 생성 벤치마크 테스트 결과, 토큰 수준에서는 73.8%의 발산이 발생했으나 실제 코드 실행 결과의 일치율은 97.6%로 나타나, 토큰 발산이 반드시 작업의 정답률 하락으로 직결되지는 않음을 확인했습니다.
*   **비용 효율성:** 위 조치는 저배치(batch size ≤ 4) 환경에서 4% 미만의 추가 지연 시간만 발생시킵니다.

## 🌍 세상에 미치는 영향 & 실무 적용 사례
*   **평가 및 디버깅:** 모델 배포 시 하드웨어 라이브러리 설정에 따라 결과가 달라질 수 있음을 인지하고, 재현성이 중요한 감사 업무나 A/B 테스트 환경에서 정밀도 통제를 위한 지침이 필요합니다.
*   **실무 적용:** 모델 서빙 시 특정 정밀도 조합에 의존하지 않고도 출력의 안정성을 높이고자 할 때, 전체 연산 정밀도를 높이는 대신 '로짓 마진'을 기준으로 한 선택적 보정 방식을 도입하여 효율적인 서빙이 가능합니다.
