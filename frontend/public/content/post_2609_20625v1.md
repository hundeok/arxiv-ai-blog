# Chronicle: LLM 에이전트의 회귀 테스트를 위한 컷-포인트 리플레이

> **원본 논문 정보**
> - **제목:** Chronicle: Cut-Point Replay for Regression Testing of LLM Agents
> - **저자:** Tisha Chawla, Susheem Koul
> - **발행일:** 2026-09-17
> - **PDF 링크:** [Chronicle: Cut-Point Replay for Regression Testing of LLM Agents](https://arxiv.org/pdf/2609.20625v1)


## ✨ 3줄 핵심 요약
- **재현 불가능성 해결:** 비결정적 특성을 가진 LLM 에이전트의 오류를 재현 가능한 기록으로 변환하여 지속적 통합(CI) 환경에서 테스트합니다.
- **컷-포인트 리플레이:** 실행 과정 중 일부는 기록된 데이터를 사용하고, 수정된 코드 구간만 실시간으로 실행하는 방식으로 효율적인 회귀 테스트를 수행합니다.
- **검증된 성능:** 6개의 오류 사례를 벤치마크한 결과, 코드 변경에 따른 오류 탐지 능력이 뛰어나며 모델 호출 없이도 동일한 결과를 20회 연속 재현했습니다.

## 📖 쉽게 풀어쓴 1분 핵심
LLM 에이전트는 같은 질문에도 매번 다른 답변을 내놓거나 외부 상태 변화에 민감하게 반응하여, 과거에 발생한 오류를 똑같이 다시 만들어내기 매우 어렵습니다. 'Chronicle'은 에이전트의 실행 과정을 '불변하는 봉투(immutable envelope)'에 담아 기록합니다. 개발자는 이 기록을 바탕으로 오류가 발생했던 구간만 수정하여 테스트할 수 있습니다. 예를 들어, 전체 과정 중 문제의 핵심이 되는 도구 사용 단계만 수정하고 나머지는 기록된 결과를 그대로 가져와 실행함으로써, 코드를 수정할 때마다 매번 에이전트를 처음부터 다시 실행하며 겪어야 했던 불확실성을 완전히 제거합니다.

## 🎯 배경 및 문제점
- **비결정적 동작:** LLM 추론 결과, 외부 도구 상태, 실행 경로의 가변성으로 인해 동일한 에이전트 코드라도 실행할 때마다 결과가 달라지는 '플래이키(flakiness)' 현상이 발생합니다.
- **재현의 어려움:** 기존의 로깅 및 평가 도구들은 발생한 일을 기록하거나 결과를 점수 매기는 데 그치며, 코드 변경 후 오류 수정 여부를 확인하는 회귀 테스트 환경을 제공하지 못합니다.

## 💡 핵심 기술 및 아키텍처
- **컷-포인트 리플레이(Cut-point Replay):** 실행 경계(boundary)를 지정하여 특정 구간은 실시간으로 코드를 실행하고, 나머지는 기록된 결과를 호출하는 기술입니다.
- **불변하는 봉투(Immutable Envelopes):** 모델 버전, 파라미터, 입력 및 출력 값을 보존하여 실행의 일관성을 유지합니다.
- **자동 탐지 및 가드:** 각 경계마다 호출 횟수를 기록하여, 코드 변경으로 인해 실행 흐름이 의도치 않게 변할 경우 이를 즉시 탐지합니다.
- **민감 정보 보호:** 기록 단계에서 기밀 정보나 개인 데이터를 자동으로 삭제하는 기능을 포함합니다.

## 📊 실험 결과 분석
- **성능 및 효율성:** 기록 시 호출당 23µs가 소요되며 이는 전체 모델 호출 시간의 약 0.008% 수준으로 매우 낮습니다.
- **안정성:** 전체 리플레이 시 모델 호출 없이 20회 반복 실행에서도 동일한 결과를 생성했습니다.
- **오류 탐지(뮤테이션 연구):** 192개의 코드 변형(mutant) 사례 중 '컷-포인트 리플레이' 방식은 모든 취약점을 성공적으로 잡아냈으나, 모든 구간을 스텁(stub) 처리한 대조군은 하나도 잡아내지 못했습니다.

## 🌍 세상에 미치는 영향 & 실무 적용 사례
- **CI/CD 통합:** 에이전트의 오류를 단 한 번의 기록으로 영구적인 회귀 테스트로 전환하여 배포 자동화의 안정성을 높입니다.
- **실무 적용:** 잘못된 환불 처리, 통화 오류, 권한 없는 파일 삭제 등 실제 에이전트 운영 중 발생한 6가지 사고를 성공적으로 테스트 사례로 구축했습니다.
- **한계점:** 현재는 스트리밍 응답이나 복잡한 병렬 도구 호출, 예외 처리 재발생 등은 지원하지 않으며, 사용자가 명시적으로 비결정적 호출 지점을 지정해야 하는 책임이 따릅니다.
