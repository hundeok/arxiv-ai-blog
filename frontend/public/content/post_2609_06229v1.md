# SWE-Test: 입력 예측을 통한 거대 언어 모델의 취약점 발견 능력 벤치마킹

> **원본 논문 정보**
> - **제목:** SWE-Test: Benchmarking LLM Vulnerability Discovery via Input Prediction
> - **저자:** Yuanxiang Shi, Jiayi Lin, Xuanyong Lin, Liangcai Su, Yeheng Duan, Wei Wang, Qi Han, Bing Zhao, Wei Hu, Xander Xu, Chenxiong Qian
> - **발행일:** 2026-09-05
> - **PDF 링크:** [SWE-Test: Benchmarking LLM Vulnerability Discovery via Input Prediction](https://arxiv.org/pdf/2609.06229v1)


## ✨ 3줄 핵심 요약
* **새로운 평가 방식:** 취약점 발견 능력을 '입력 예측(Input Prediction)' 작업으로 재정의하여, 결정론적 정답을 가진 정교한 벤치마킹 환경을 구축했습니다.
* **단계별 능력 분석:** 코드 이해, 피드백 기반 수정, 경로 탐색 능력을 분리하여 평가할 수 있도록 세 가지 작업 모드를 제공합니다.
* **주요 발견:** 에이전트의 취약점 발견 실패의 가장 큰 병목 구간은 '제약 조건 추론(Constraint Inference)'이며, 피드백 제공 시 성능이 크게 향상됨을 확인했습니다.

## 📖 쉽게 풀어쓴 1분 핵심
기존의 소프트웨어 취약점 탐지 평가는 훈련 데이터 오염 문제나 모호한 정답 설정으로 인해 에이전트의 실제 능력을 측정하기 어려웠습니다. 'SWE-Test'는 실제 C/C++ 프로그램에서 퍼징(fuzzing)을 통해 검증된 목표 지점에 도달할 수 있는 '입력값'을 에이전트가 찾아내도록 함으로써, 에이전트가 코드를 얼마나 정확히 이해하고 복잡한 조건을 해결하는지 객관적으로 측정합니다. 이 벤치마크는 에이전트가 경로를 찾는 능력과 제약 조건을 만족시키는 능력을 각각 평가하여, 단순히 결과를 맞히는 것을 넘어 어디에서 실패하는지 구체적으로 진단할 수 있게 합니다.

## 🎯 배경 및 문제점
* **기존 평가의 한계:** 과거의 보안 벤치마크는 에이전트의 학습 데이터에 포함될 위험(데이터 오염)이 크고, 이미 알려진 버그 리스트에만 의존하여 확장성이 낮습니다.
* **엔드투엔드 평가의 모호성:** 기존의 단일 결과 보고 방식으로는 에이전트가 코드 이해에 실패했는지, 피드백을 활용하지 못했는지 등 구체적인 실패 원인을 파악할 수 없습니다.
* **취약점의 복잡성:** 취약점 발견은 코드 이해, 입력값 생성, 실행 및 피드백을 통한 수정이 결합된 고도의 복합적인 능력입니다.

## 💡 핵심 기술 및 아키텍처
* **입력 예측 기반 측정:** 60개의 고정 타깃 작업(Open-loop 및 Feedback-enabled)을 통해 코드 이해와 수정 능력을 분리 측정합니다.
* **세 가지 평가 모드:**
    1. **Open-loop:** 피드백 없이 코드 이해력만 평가.
    2. **Feedback-enabled:** 실행 피드백을 제공하여 에이전트의 수정 능력을 평가.
    3. **Online Arena:** 미리 정의된 타깃 없이, 퍼저(fuzzer)가 도달하지 못한 경로를 에이전트가 스스로 탐색하는 능력 평가.
* **데이터 구성:** 22개의 실제 C/C++ 프로그램과 15개 도메인을 활용하여 실무 환경을 반영했습니다.

## 📊 실험 결과 분석
* **성능 수치:** 15개의 모델-스캐폴드 구성 중 피드백 사용 모드에서의 최고 성공률은 55.0%였습니다.
* **피드백의 효과:** 7개 Claude Code 구성 비교 결과, 피드백 사용 시 평균 성공률이 19.3%(피드백 없음)에서 36.4%(피드백 있음)로 상승했습니다.
* **병목 현상:** 코드 네비게이션보다는 '제약 조건 추론(Constraint Inference)'이 실패의 주요 원인으로 밝혀졌습니다.
* **변수 영향:** 모델 자체의 능력 외에도 '스캐폴드(Scaffold) 선택'과 '추론 노력(Reasoning effort)' 설정에 따라 성능 차이가 크게 나타났습니다.

## 🌍 세상에 미치는 영향 & 실무 적용 사례
* **객관적 지표 마련:** 보안 에이전트의 취약점 발견 능력을 신뢰성 있게 평가할 표준을 제공합니다.
* **에이전트 최적화 방향 제시:** 개발자들은 에이전트가 코드 이해나 제약 조건 추론 중 어디에 취약한지 파악하여 모델을 개선할 수 있습니다.
* **보안 생태계 기여:** 실제 C/C++ 오픈소스 프로젝트의 코드를 대상으로 하므로, 소프트웨어 공급망 보안을 강화하는 AI 도구 개발의 실질적인 나침반 역할을 합니다.
