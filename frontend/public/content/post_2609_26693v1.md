# 모델이 아닌 서빙 스택 측정하기: 로컬 도구 사용 평가의 숨겨진 혼란 변수

> **원본 논문 정보**
> - **제목:** Measuring the Serving Stack Instead of the Model: Hidden Confounds in Local Tool-Use Evaluation
> - **저자:** Lijuan Tang, Yuemeng Zheng
> - **발행일:** 2026-09-22
> - **PDF 링크:** [Measuring the Serving Stack Instead of the Model: Hidden Confounds in Local Tool-Use Evaluation](https://arxiv.org/pdf/2609.26693v1)


## ✨ 3줄 핵심 요약
* 로컬 모델의 도구 사용 능력을 평가할 때, 모델 자체보다 '서빙 스택(Ollama, vLLM 등)'의 설정이 평가 결과에 결정적인 영향을 미치는 혼란 변수로 작용합니다.
* 서빙 계층이 모델의 도구 호출 요청을 사전에 거부하거나 잘못 처리해도 이를 구조적 실패로 기록하지 않아, 유능한 모델도 '도구 사용 능력 0%'로 잘못 측정될 수 있습니다.
* 정확한 평가를 위해서는 서빙 환경을 고정하고, 서버에 의한 요청 거부와 모델의 실제 호출 실패를 구분하며, 데이터 편향을 막기 위해 시드별(per-seed) 분석을 수행해야 합니다.

## 📖 쉽게 풀어쓴 1분 핵심
AI 모델이 도구를 사용하려면 먼저 서버(서빙 스택)가 이 요청을 받아들여야 합니다. 그러나 연구 결과, Ollama나 vLLM 같은 서빙 소프트웨어들은 모델의 성능과 상관없이 특정 모델에 대해 "도구 사용 불가능"이라는 사전 설정을 강제합니다. 평가 도구는 서버가 모델을 실행조차 하지 않고 거부한 상황을 모델이 스스로 도구 사용을 포기한 것으로 오인하여 잘못된 성적표를 매깁니다. 즉, 지금의 평가는 '모델의 지능'이 아닌 '서버의 설정'을 측정하고 있을 가능성이 큽니다.

## 🎯 배경 및 문제점
로컬 코딩 에이전트의 도구 사용 성공률을 측정할 때, 평가 환경(Harness)은 모델에 도구 목록을 보냅니다. 하지만 서빙 계층은 모델 호출 전 단계에서 이 요청을 가로챕니다. 
* **구조적 결함:** 서버가 요청을 거부(HTTP 400 등)해도 평가 시스템은 이를 구조적인 실패로 기록하지 않고, 단순히 모델이 도구를 호출하지 않은 것으로 처리합니다.
* **통계적 오류:** 시드별 데이터가 부족하거나, 반복적인 루프를 도는 에이전트의 결과가 결과값 전체를 왜곡(Pool 분석의 한계)하여 통계적 신뢰도가 낮아집니다.

## 💡 핵심 기술 및 아키텍처
연구팀은 Ollama, llama.cpp, vLLM, SGLang 등 주요 서빙 스택을 비교 분석했습니다. 
* **서빙 게이팅:** 모델 자체의 능력보다 서빙 스택의 설정(정적 템플릿 플래그)에 따라 호출 방식이 결정됩니다. (예: 어떤 모델은 텍스트로 응답하고, 어떤 모델은 시스템에서 원천 차단됨)
* **제약된 디코딩(Constrained Decoding):** 모델이 형식에 맞는 응답을 강제하도록 설정할 경우 파싱 실패는 해결되지만, 반대로 모델이 종료 조건을 찾지 못해 무한 루프에 빠지는 '종료 실패' 문제가 발생합니다.

## 📊 실험 결과 분석
* **서버별 차이:** 동일한 요청임에도 Ollama, vLLM, SGLang은 각각 다르게 반응합니다. vLLM은 특정 플래그 설정 없이는 요청을 outright 거부하며, 이는 모델의 능력과는 무관합니다.
* **측정 데이터의 변동성:** 통계 분석에서 '시드별(per-seed)' 수치와 '전체 통합(pooled)' 수치가 최대 약 55포인트까지 차이 났습니다. 
* **신뢰 구간:** 약한 모델들의 경우 95% 신뢰 구간이 매우 넓어(예: 12~75) 모델 간 성능 순위를 매기는 것이 불가능한 수준이었습니다.

## 🌍 세상에 미치는 영향 & 실무 적용 사례
* **평가 방법론 개선:** 향후 로컬 에이전트 평가 시 모델 정보뿐만 아니라 '서빙 스택', '버전', '도구 호출 파서 설정'을 반드시 함께 기록해야 합니다.
* **공정 비교:** 모델을 비교할 때는 반드시 서빙 환경을 고정해야 하며, '서버에 의한 요청 거부'를 모델의 능력 부족과 명확히 구분하는 분석 체계가 도입되어야 합니다.
* **실무적 제언:** 연구팀은 서빙 스택의 행동을 평가 프로토콜의 일부로 간주하는 체크리스트 준수를 권고합니다.
