# 도구에게 물어보라, 추측하지 마라: 에이전트 도구 호출은 진행 상황을 담고 있으며, 서빙 시스템은 이를 읽어야 한다

> **원본 논문 정보**
> - **제목:** Ask the Tool, Don't Guess: Agent Tool Calls Hold Their Progress, and the Serving System Should Read It
> - **저자:** Yipeng Liu, Yingqiang Zhang, Feifei Li, Huanchen Zhang
> - **발행일:** 2026-09-16
> - **PDF 링크:** [Ask the Tool, Don't Guess: Agent Tool Calls Hold Their Progress, and the Serving System Should Read It](https://arxiv.org/pdf/2609.18849v1)


## ✨ 3줄 핵심 요약
- AI 에이전트가 도구를 사용하는 동안 GPU 메모리(KV 캐시)가 비효율적으로 점유되는데, 현재의 서빙 시스템은 도구의 완료 시간을 단순히 추측에 의존하여 처리하고 있습니다.
- 연구진은 도구가 실행 중 출력하거나 남기는 정보를 수집하는 '하네스(harness)'를 개발하여, 에이전트가 보는 결과값은 유지하면서도 도구의 실제 진행률을 실시간으로 파악했습니다.
- 실제 엔진에 적용한 결과, 도구 호출 후 첫 토큰 생성 시간(TTFT)을 기존 방식 대비 20% 이상 단축하며 성능을 크게 개선했습니다.

## 📖 쉽게 풀어쓴 1분 핵심
AI 에이전트가 코딩이나 데이터 분석 등 복잡한 작업을 수행할 때, 도구(컴파일러, 테스트 툴 등)가 실행되는 동안 모델은 아무 일도 하지 않으면서 GPU 자원을 점유합니다. 시스템은 이 도구가 얼마나 걸릴지 예측해야 하는데, 현재 방식은 과거 데이터나 도구 이름만 보고 대충 추측하는 수준입니다. 논문은 "도구는 이미 자신이 얼마나 끝났는지 알고 있다"는 점에 주목합니다. 연구진은 도구가 뱉어내는 로그나 파일 생성 상태를 가로채 진행 상황을 정밀하게 파악하는 시스템을 구축했습니다. 이를 통해 시스템은 자원을 더 똑똑하게 회수하거나 유지할 수 있게 되었고, 결과적으로 AI의 반응 속도가 훨씬 빨라졌습니다.

## 🎯 배경 및 문제점
- **자원 낭비:** 에이전트가 도구 결과를 기다리는 동안 GPU 메모리의 KV 캐시는 아무런 유효한 작업을 수행하지 않음에도 메모리를 계속 점유합니다.
- **예측의 한계:** 기존 서빙 시스템은 도구의 이름, 과거 기록, 선언된 기간 등을 통해 실행 시간을 예측하지만, 실행 중인 도구의 실제 상태를 반영하지 못해 정확도가 매우 낮습니다.
- **정보 차단:** 도구는 실행 중 진행 상황을 알 수 있는 정보를 생성하지만, 에이전트 환경(silent flags, 리다이렉트 등)이 이를 숨기거나 제거하여 시스템이 이를 활용할 수 없습니다.

## 💡 핵심 기술 및 아키텍처
- **하네스(Harness) 시스템:** 도구 실행 프로세스와 에이전트 사이에 위치하여 도구가 내보내는 출력과 파일 시스템의 변화를 실시간으로 모니터링합니다.
- **사이드 채널(Side Channel):** 에이전트가 받는 출력물은 원본 그대로 유지하면서, 진행 상황에 대한 메타 데이터(완료율, 진행 단계 등)만 별도로 추출하여 서빙 컨트롤러에 전달합니다.
- **3단계 정보 추출:** 
    1. 환경 설정으로 가려진 진행 막대 복원 및 읽기.
    2. 도구의 verbose(상세 출력) 모드를 활용한 정보 확보.
    3. 에이전트가 작성한 코드 내에 진행 상황 출력 로직을 삽입하여 관찰.

## 📊 실험 결과 분석
- **정확도:** 제안된 방식은 기존의 어떤 예측 기법보다 진행 상황 파악 능력이 몇 배에서 최대 10배 이상 정확했습니다.
- **성능 향상:** 프로덕션 환경 엔진에 적용 시, 도구 호출 후 첫 토큰 생성 시간(TTFT)이 LRU(최근 최소 사용) 방식 대비 HBM 전용 환경에서 20.7%, HBM+DRAM 환경에서 20.8% 단축되었습니다.
- **안정성:** 도구의 진행 상황을 추출하는 과정이 에이전트의 벤치마크 점수에 영향을 미치지 않음을 확인했습니다.

## 🌍 세상에 미치는 영향 & 실무 적용 사례
- **서빙 효율화:** AI 인프라 운영 측면에서 GPU 자원 점유 최적화는 비용 절감과 처리량(throughput) 증대로 직결됩니다.
- **도구 설계의 변화:** 향후 도구 개발 시, 도구가 자체적으로 상태를 외부에 노출하는 방식을 채택한다면 별도의 하네스 없이도 즉각적인 자원 관리가 가능해질 것입니다.
- **주의사항:** 진행 보고는 사용자가 제어하는 콘텐츠에 의해 조작될 수 있으며, 사이드 채널을 통한 작업 구조 노출은 보안적으로 민감한 정보로 취급되어야 한다는 윤리적 고려 사항이 언급되었습니다.
