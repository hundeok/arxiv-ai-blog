# SWE-Touch: 사용자가 코드를 수정하는 환경에서 코딩 에이전트 벤치마킹하기

> **원본 논문 정보**
> - **제목:** SWE-Touch: Benchmarking Coding Agents When Users Touch the Code
> - **저자:** Yuqiao Tan, Jinxiang Meng, Fangyu Lei, Minzheng Wang, Shizhu He, Jun Zhao, Kang Liu
> - **발행일:** 2026-08-03
> - **PDF 링크:** [SWE-Touch: Benchmarking Coding Agents When Users Touch the Code](https://arxiv.org/pdf/2608.02499v1)


## ✨ 3줄 핵심 요약
* **현실 반영형 벤치마크**: 실제 소프트웨어 개발 환경처럼, 코딩 에이전트가 작업하는 동안 사용자가 실시간으로 코드를 수정(Counter-Edit)하는 상황을 테스트합니다.
* **성능 저하 확인**: 사용자의 개입이 발생할 경우, 기존 코딩 에이전트들은 평균 해결률이 7.7%p 하락하는 등 변화된 환경을 인식하고 적응하는 데 어려움을 겪습니다.
* **핵심 과제 도출**: 에이전트가 작업 공간의 변경 사항을 감지하고, 상충하는 편집 내용을 조정하며, 수정된 코드를 검증하는 능력이 향상되어야 함을 시사합니다.

## 📖 쉽게 풀어쓴 1분 핵심
대부분의 코딩 에이전트 평가는 에이전트가 홀로 코드를 작성하는 정적인 환경에서 이루어집니다. 그러나 실제 개발 현장에서는 개발자와 AI가 같은 코드를 공유하며 함께 수정합니다. 이 논문은 사용자가 코드 수정이라는 방식으로 작업에 개입할 때 AI가 어떻게 대응하는지를 평가하는 'SWE-Touch' 프레임워크를 제안합니다. 실험 결과, 현재의 강력한 AI 모델들도 코드의 상태가 바뀌었을 때 이를 제대로 파악하지 못하고 이전의 잘못된 정보를 고수하거나, 변경된 코드를 충분히 재검증하지 않아 실패하는 경우가 많음을 확인했습니다.

## 🎯 배경 및 문제점
* 기존 벤치마크(SWE-Bench 등)는 에이전트가 단독으로 작업을 완료하는 정적인 방식에 초점이 맞춰져 있습니다.
* 실제 프로젝트의 약 59% 세션에서 사용자에 의한 저장소 변경이 발생함에도 불구하고, 이를 고려한 평가는 부족했습니다.
* AI가 사용자의 실시간 코드 수정(Counter-Edit)을 마주했을 때, 변경된 코드 환경을 인지하고 적응하는 능력이 제대로 검증되지 않았습니다.

## 💡 핵심 기술 및 아키텍처
* **SWE-Touch 프레임워크**: 작업과 상충하는 타당한 코드 수정본(Counter-Edits)을 생성하여 주입하는 스트레스 테스트 방식입니다.
* **User Patch Generator**: GPT-5.5를 활용하여 작업 관련 코드 영역을 분석하고, 맥락에 맞는 사용자 개입 편집본을 생성합니다.
* **평가 방법**: 에이전트가 코드 저장소의 변화를 인지하고, 수정된 코드에 맞춰 전략을 수정하는지 확인합니다. 코드 저장소 접근 시 변경 여부를 감지하는 트리거 시스템을 사용합니다.

## 📊 실험 결과 분석
* **해결률 하락**: 'SWE-bench Verified' 테스트에서 사용자의 개입(Counter-Edit)이 발생했을 때 에이전트들의 평균 해결률이 7.7%p 감소했습니다.
* **모델별 차이**: 9개 모델 중 7개 모델에서 토큰 소비량이 증가했습니다(예: Claude Opus 4.8 37.8% 증가). GPT 5.5와 Kimi K2.6은 오히려 작업 단계(Steps)가 줄어들었으나, 전반적인 성능 저하는 공통적으로 나타났습니다.
* **실패 원인**: 에이전트가 변경된 환경을 제대로 재검증하지 않고 이전에 학습한 잘못된 상태를 유지하거나, 충돌하는 코드를 적절히 처리하지 못하는 '상태 인식 부족' 현상이 발견되었습니다.

## 🌍 세상에 미치는 영향 & 실무 적용 사례
* **차세대 AI 협업 모델**: 본 연구는 단순한 자동화를 넘어, 인간과 AI가 실시간으로 소통하며 협업하는 '공유 작업 공간' 중심의 에이전트 설계 방향을 제시합니다.
* **실무 적용 가이드**: 에이전트가 더 나은 협업자가 되기 위해서는 '작업 공간의 변화 감지', '충돌하는 편집 내용의 논리적 조정', '변경 사항에 대한 검증' 능력이 필수적임을 시사합니다.
* **향후 연구 방향**: 단순 코딩 능력을 넘어, 인간의 피드백을 실시간 환경에서 어떻게 유연하게 수용할 것인가에 대한 정량적 평가 지표로 활용될 것으로 기대됩니다.
