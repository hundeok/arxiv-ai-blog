# StateAct: 장기 컴퓨터 작업 에이전트를 위한 픽셀 대신 프로그램 상태 활용

> **원본 논문 정보**
> - **제목:** StateAct: Program State, before Pixels, for Long-Horizon Computer-Use Agents
> - **저자:** Yan Yang, Xiangru Jian, Ziyang Luo, Zirui Zhao, Yutong Dai, Ziji Shi, Hanshu Yan, Jun Hao Liew, Silvio Savarese, Junnan Li
> - **발행일:** 2026-07-24
> - **PDF 링크:** [StateAct: Program State, before Pixels, for Long-Horizon Computer-Use Agents](https://arxiv.org/pdf/2607.22798v1)


## ✨ 3줄 핵심 요약
* **상태 중심 접근:** 에이전트가 화면(픽셀) 대신 파일, 백엔드, DOM 등 실제 '프로그램 상태'를 직접 조작하도록 설계하여 성능과 효율을 개선함.
* **전문화된 역할 분담:** 메인 에이전트는 상태 제어에 집중하고, 꼭 필요한 경우에만 GUI 하위 에이전트가 화면 상호작용을 처리하여 비용을 대폭 절감함.
* **독립적 검증 시스템:** '피니시 게이트(Finish Gate)'를 도입해 에이전트의 자기 서술에 의존하지 않고, 최종 결과물 상태를 독립적으로 검증함.

## 📖 쉽게 풀어쓴 1분 핵심
기존 컴퓨터 사용 에이전트는 화면에 무엇이 보이는지(픽셀) 해석하는 데 의존해 왔습니다. 하지만 화면은 정보가 손실된 결과물일 뿐입니다. StateAct는 에이전트가 마치 개발자처럼 파일이나 코드 기반의 데이터(프로그램 상태)를 직접 들여다보고 수정하도록 만듭니다. 화면 조작이 꼭 필요한 아주 드문 순간(전체 작업의 1.1%)에만 전용 도우미(GUI 하위 에이전트)를 호출합니다. 결과적으로 에이전트는 "눈으로 보는 것"보다 "실제 데이터"를 정확히 이해하게 되어, 훨씬 복잡한 장기 작업을 오류 없이 처리할 수 있게 됩니다.

## 🎯 배경 및 문제점
* **인식의 한계:** 픽셀 기반 정보는 데이터의 속성(예: 수식이 들어간 셀과 결과값만 적힌 셀)을 구분하기 어렵고, 작업을 반복할수록 오차가 누적됩니다.
* **장기 작업의 어려움:** 수백 단계의 작업을 수행할 때, 화면 정보만으로는 결과물이 최종적으로 올바르게 저장되었는지 확신할 수 없습니다.
* **비용과 성능의 불균형:** 고성능 모델을 화면 해석에만 매달리게 하면 계산 비용은 높지만, 정작 중요한 논리적 판단 정확도는 낮아지는 문제가 발생합니다.

## 💡 핵심 기술 및 아키텍처
* **State-Grounding(상태 기반 접지):** 화면 인식 대신 프로그램 내부 상태(파일, 데이터베이스 등)를 직접 접근하여 제어합니다.
* **하위 에이전트 위임:** 시각적 조작이 필수적인 상황(드래그, 모달 종료 등)에만 GUI 전용 에이전트가 개입합니다.
* **독립적 피니시 게이트:** 에이전트의 이전 기억을 공유하지 않는 별도의 검증 모듈이 파일 등을 직접 확인하여 작업 완료 여부를 판단합니다.
* **컨텍스트 관리:** 장기 작업을 위해 긴 기억을 요약하고 외부 체크리스트를 유지하여 에이전트의 문맥 집중도를 높입니다.

## 📊 실험 결과 분석
* **성능 향상:** OSWorld 2.0 벤치마크에서 Claude Opus 4.8 모델 기준, 이진 성공률이 20.6%에서 26.9%로, 부분 성공률이 54.8%에서 61.6%로 향상되었습니다.
* **비용 절감:** 동일한 모델을 사용하더라도 기존 방식 대비 작업당 비용이 약 9배 저렴하게 산출되었습니다.
* **분석 결과:** 성능 향상은 모델 자체의 지능보다는 에이전트가 "무엇을 관찰하는지(픽셀이 아닌 상태)"에 기인합니다. 
* **검증 시스템:** 피니시 게이트는 정답을 맞힌 성공 사례의 96.6%를 올바르게 통과시켰으며, 88.9%의 정확도로 잘못된 결과물을 걸러냈습니다.

## 🌍 세상에 미치는 영향 & 실무 적용 사례
* **컴퓨터 에이전트의 패러다임 변화:** 단순히 "보는 AI"에서 "데이터를 다루는 AI"로 에이전트 설계의 중심이 이동할 것임을 시사합니다.
* **실무 적용 가능성:** 특정 소프트웨어의 API나 파일 시스템 접근이 가능한 환경이라면, 반복적인 문서 작성, 데이터 정리, 시스템 설정 변경 등 장기 컴퓨터 자동화 작업의 신뢰도를 크게 높일 수 있습니다.
* **한계 및 전망:** 시스템의 오류는 이제 시각적인 인식 실패가 아닌, 에이전트의 '추론 과정'에서 발생하므로 앞으로는 AI의 논리적 사고력을 강화하는 방향으로 연구가 집중될 것으로 보입니다.
