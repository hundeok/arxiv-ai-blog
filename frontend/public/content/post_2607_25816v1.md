# 추론하면서 추측하기: 공동 에이전트-예측기 강화학습을 통한 에이전트의 다음 도구 호출 예측 학습

> **원본 논문 정보**
> - **제목:** Speculate While You Reason: Teaching Agents to Predict Their Next Tool Call via Joint Agent-Speculator RL
> - **저자:** Jiabao Ji, Yujian Liu, Li An, Rohit Jain, Gungor Polatkan, Siyu Zhu, Shiyu Chang
> - **발행일:** 2026-07-28
> - **PDF 링크:** [Speculate While You Reason: Teaching Agents to Predict Their Next Tool Call via Joint Agent-Speculator RL](https://arxiv.org/pdf/2607.25816v1)


## ✨ 3줄 핵심 요약
* 기존의 외부 도구 예측 모델과 에이전트 간의 불일치(speculator-agent gap) 문제를 해결하기 위해, 에이전트 스스로 다음 도구 호출을 예측하는 '자기 예측 에이전트(self-speculating agent)'를 제안함.
* 강화학습을 통해 동일한 모델 내에서 에이전트 모드와 예측기 모드를 모두 수행하며, KV 캐시를 재사용하여 도구 호출 대기 시간을 줄임.
* SearchQA 및 대화형 도구 사용 작업에서 이전 모델 대비 도구 호출 예측 정확도를 유의미하게 향상시킴.

## 📖 쉽게 풀어쓴 1분 핵심
대규모 언어 모델 기반 에이전트가 외부 도구(검색, 데이터베이스 등)를 사용할 때 가장 큰 병목 현상은 도구 호출 결과가 나올 때까지 기다리는 '대기 시간'입니다. 이를 해결하기 위해 미리 다음에 호출할 도구를 예측하고 실행하는 '도구 호출 예측' 방식이 존재하지만, 기존에는 이를 위해 별도의 보조 모델을 따로 두어야 했습니다. 이 논문은 별도의 모델 없이, 에이전트 본체가 스스로 다음 호출을 예측하게 만드는 '자기 예측 에이전트'를 제안합니다. 이는 에이전트가 수행한 실제 결과물을 학습 데이터로 활용하여, 도구 호출 지연 시간을 효과적으로 숨기면서도 작업 성공률을 유지합니다.

## 🎯 배경 및 문제점
* **대기 시간 문제:** 에이전트가 도구를 호출하면 결과를 얻기까지 네트워크 지연 등이 발생하여 추론 시간의 상당 부분이 대기로 소모됨.
* **예측기-에이전트 간극:** 기존 도구 예측 모델(speculator)은 별도의 독립된 모델로 운영되는 경우가 많아, 정작 에이전트가 수행하려는 실제 행동과 예측 간의 불일치가 발생함.
* **자원 낭비:** 별도의 보조 모델과 독립적인 KV 캐시를 운용하는 것은 시스템 복잡도를 높이고 효율성을 떨어뜨림.

## 💡 핵심 기술 및 아키텍처
* **자기 예측 에이전트(Self-speculating Agent):** 별도 모델 없이 단일 모델이 에이전트 모드와 예측기 모드를 겸함. 예측기 모드에서는 부분적인 추론 경로(trajectory)를 보고 다음 도구 호출을 예측함.
* **공동 강화학습(Joint Agent-Speculator RL):** 에이전트의 실제 수행 결과(rollouts)를 예측기의 학습 타겟으로 활용하며, 두 모드를 교대로 업데이트함.
* **학습 안정화 기법:** RL 시작 전 SFT(지도 미세 조정) 워밍업, 모드 전환 시 최적화 상태(optimizer state) 초기화, 무의미한 도구 반복 호출에 대한 페널티 부여 등을 통해 학습 효율을 높임.

## 📊 실험 결과 분석
* **예측 성능 향상:** Qwen3-4B 모델의 경우 다음 도구 호출 Hit@1 정확도가 44.1에서 61.2로, Qwen3.5-4B 모델은 48.9에서 66.3으로 크게 향상됨.
* **성능 유지:** 도구 호출 예측 정확도를 높이면서도, 에이전트 본연의 작업 성공률은 기존 수준을 유지함.
* **데이터:** 논문 내 실험 결과 수치는 제시된 성능 지표(Hit@1)에 근거함.

## 🌍 세상에 미치는 영향 & 실무 적용 사례
* **대기 시간 단축:** 실시간 데이터 검색이나 복잡한 API 호출이 빈번한 환경에서 에이전트의 응답 속도를 획기적으로 개선할 수 있음.
* **적용 범위:** 읽기 전용 도구(검색, 데이터베이스 조회 등) 환경에 즉시 적용 가능하며, 도구 호출 시 발생하는 오버헤드를 효과적으로 상쇄함.
* **주의사항:** 데이터 변경이나 결제 등 외부 상태를 변화시키는 도구 호출에는 부적합할 수 있으며, 실제 서비스 시에는 안전한 호출과 상태 변화 호출을 구분하는 정책이 필요함.
