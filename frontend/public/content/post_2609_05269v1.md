# CONTINUITY: 구성 가능한 LLM 에이전트 제어를 위한 보안-문맥 계약

> **원본 논문 정보**
> - **제목:** CONTINUITY: Security-Context Contracts for Composable LLM Agent Controls
> - **저자:** Chris Zheng, Geng Yang
> - **발행일:** 2026-09-04
> - **PDF 링크:** [CONTINUITY: Security-Context Contracts for Composable LLM Agent Controls](https://arxiv.org/pdf/2609.05269v1)


## ✨ 3줄 핵심 요약
* LLM 에이전트의 다양한 보안 제어(인증, 정책 등)가 복합적으로 구성될 때 발생하는 정보 유실 및 보안 결함을 '보안-문맥 불연속성(Security-context discontinuity)'으로 정의했습니다.
* 이를 해결하기 위해 '종단간 결과 무결성(ECI)' 모델과 이를 강제하는 참조 시스템 'Continuity'를 도입했습니다.
* 실험 결과, 3,460개의 시나리오에서 128개의 모든 보안 결함 클래스를 차단하고 유해한 효과 발생을 성공적으로 막았습니다.

## 📖 쉽게 풀어쓴 1분 핵심
최근 LLM 에이전트는 웹 정보 검색, 외부 도구 실행, 작업 위임 등 복잡한 과정을 거칩니다. 이 과정에서 인증(인그레스), 정책 확인, 어댑터 변환 등 여러 보안 장치가 순차적으로 작동하는데, 단계가 넘어갈 때마다 중요한 보안 정보가 사라지거나 왜곡되는 문제가 발생합니다. 이로 인해 공격자가 침투할 틈이 생깁니다. 'Continuity'는 각 보안 단계마다 '계약(Contract)'을 맺어, 최종 실행 직전까지 데이터의 출처와 허가 범위를 증명하게 함으로써 보안상의 빈틈을 원천 봉쇄하는 기술입니다.

## 🎯 배경 및 문제점
LLM 에이전트는 외부 데이터를 받아 계획을 세우고 도구를 호출하는 과정에서 유해한 데이터에 노출될 가능성이 큽니다. 시스템은 이를 막기 위해 여러 방어 기법을 사용하지만, 이들이 결합할 때 다음과 같은 **보안-문맥 불연속성** 문제가 발생합니다.
* 보안 경계에서 출처 표기(Source label) 누락
* 잘못된 권한 부여(Delegation) 확장
* 승인된 필드가 타당한 근거 없이 변경됨
* 만료되었거나 재사용된 허가증 실행

## 💡 핵심 기술 및 아키텍처
'Continuity' 시스템은 **종단간 결과 무결성(ECI)**을 확보하기 위해 다음 기술을 사용합니다.
* **가정-보장(Assume-guarantee) 계약 모델:** 각 단계(메모리, 게이트웨이, 어댑터)가 이전 단계의 보안 상태를 보장하도록 강제합니다.
* **RFC 6901 스타일 필드 경로:** 데이터의 특정 부분을 세밀하게 추적하여 변경 사항을 검증합니다.
* **변환 증인(Transformation witness):** 데이터 변환 시 정당한 근거가 있음을 증명합니다.
* **최종성 허가(Finality permit):** 최종 실행 단계에서 주제, 액션, 정책, 재사용 방지 토큰 등이 일치하는지 확인합니다.

## 📊 실험 결과 분석
1.5KLOC(코드 라인 수) 규모의 프로토타입을 통해 3,460개 시나리오 및 24,220번의 시스템 실행을 검증했습니다.
* **안전성:** 128개의 모든 보안 결함 클래스를 완벽히 제어했으며, 2,560개의 공격 시도에서 유해한 효과를 0건 기록했습니다.
* **성능:** 중간값 기준 증명 검증(Proof verification)에는 4.21ms, 종단간 처리에 7.17ms가 소요되었습니다.
* **비교:** 보안 장치가 불완전한 참조 구성에서는 공격의 65.6%에서 유해한 효과가 발생하여, 본 시스템의 효과를 입증했습니다.
* *주의: 본 결과는 특정 신뢰 컴퓨팅 모델 내에서의 결정론적 결과이며, 실제 세상의 공격 확률에 대한 예측은 아닙니다.*
