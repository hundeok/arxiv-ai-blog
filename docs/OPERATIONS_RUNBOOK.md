# 운영 런북

## 매주 10분 점검

1. GitHub Actions 최근 실행이 성공인지 확인한다.
2. `pipeline-status.json`에서 `retry_count`, `review_count`, 마지막 실행, 일일 추정 비용을 확인한다.
3. 배포 주소에서 최신 글 하나와 오래된 글 하나를 열어 본다.
4. GA4 Realtime 또는 표준 보고서에서 `/`와 `/papers/...` 페이지뷰를 확인한다.
5. Search Console에서 색인·제외·사이트맵 오류를 확인한다.

## 장애 분류와 조치

| 증상 | 우선 확인 | 조치 |
| --- | --- | --- |
| 새 글 0건 | Actions 로그, `review/retry`, 예산 | 원인만 수정하고 큐는 보존 |
| 429/일시 API 오류 | `next_retry_at`, 시도 횟수 | backoff가 처리하도록 두고 수동 반복 실행 금지 |
| 비용 급증 | `usage_total`, 모델/배치/예산 env | 배치를 낮추고 일일 예산을 먼저 제한 |
| 논문 404 | metadata `filename`과 실제 Markdown | 재생성 후 배포 확인 |
| sitemap 오류 | `/sitemap-index.xml`, `/sitemap.xml` 실제 응답 | XML을 고친 뒤 Search Console 재제출 |
| GA4 0 | 태그 ID, 실시간 보고서, 브라우저 차단기 | 코드 배포 여부부터 확인 |

## 안전한 변경 순서

1. 사용자 생성·미추적 파일을 건드리지 않고 `git status --short`를 기록한다.
2. 단위 테스트와 production build를 실행한다.
3. 데이터 계약 변경이면 기존 JSON을 재생성하고 샘플을 확인한다.
4. 커밋 전 `git diff --check`와 테스트를 통과시킨다.
5. push 뒤 Vercel Ready 및 운영 페이지를 확인한다.

## AdSense 재신청 체크리스트

- [ ] 소개, 운영·AI 고지, 개인정보, 실제 공개 문의 수단이 있다.
- [ ] 원문 출처·AI의 역할·정정/권리 요청 경로가 명확하다.
- [ ] 주제별 탐색과 관련 글 이동이 가능하다.
- [ ] 핵심 후보 중 사람이 편집한 독창 해설이 누적돼 있다.
- [ ] 모바일에서 광고 없이도 읽기·탐색 경험이 완결된다.
- [ ] 2~4주 이상 정상 색인/방문 데이터가 쌓였다.

문의 수단은 운영자가 통제하는 공개 이메일 또는 공개 이슈 트래커여야 한다. 아직 준비되지 않았다면 ‘준비 중’ 문구로 재신청하지 않는다.
